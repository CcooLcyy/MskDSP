# 开发容器说明

本文档说明如何稳定复用 `mskdsp-dev` 开发容器，并让容器内的 `vcpkg` 流程与 CI 保持一致。

## 目标

- 保留容器名 `mskdsp-dev`
- 保留工作目录 `/data/code/mskdsp`
- 保留脚本兼容路径 `/data/3rdlibs/vcpkg`
- 让 `/data/3rdlibs/vcpkg` 改为容器专管，不再复用宿主机同路径内容
- 将宿主机 `/home/code/.codex` 只读挂载到 `/codex-sync`
- 用容器专用卷承载 `/root/.codex`，避免宿主机 `.codex` 被 `root` 改属主
- 容器启动时按仓库 `vcpkg-configuration.json` 中的 baseline 自动校验或重建 `vcpkg`
- 容器从 `/codex-sync` 实时读取宿主机 `Codex` 配置，并把认证状态同步到容器私有 `/root/.codex`

## 1. 构建并启动开发容器

```bash
bash script/devcontainer/start_mskdsp_dev.sh
```

该脚本会按需构建镜像、创建命名卷并启动长期驻留的 `mskdsp-dev` 容器。

如只想复用现有镜像、不重新 build：

```bash
bash script/devcontainer/start_mskdsp_dev.sh --no-build
```

如需强制重建容器：

```bash
bash script/devcontainer/start_mskdsp_dev.sh --recreate
```

镜像内会预装：

- `gcc-14` / `g++-14`
- `cmake`
- `ninja`
- `gcovr`
- `aarch64-linux-gnu-gcc` / `aarch64-linux-gnu-g++`
- `curl`
- `patchelf`

同时会固化以下环境变量：

- `VCPKG_ROOT=/data/3rdlibs/vcpkg`
- `VCPKG_DOWNLOADS=/root/.cache/vcpkg/downloads`
- `VCPKG_DEFAULT_BINARY_CACHE=/root/.cache/vcpkg/archives`
- `CCACHE_DIR=/root/.cache/ccache`
- `VCPKG_DISABLE_METRICS=1`

另外，镜像会把默认 `gcc/g++/cc/c++` 切到 14，保证 `x64` 默认使用 GCC 14，同时不通过全局 `CC/CXX` 污染 `arm64` 交叉编译流程。

## 2. 卷说明

启动脚本首次运行时会自动创建以下卷：

卷的用途如下：

- `mskdsp-codex-home`：容器专管的 `/root/.codex`
- `mskdsp-vcpkg-root`：容器专管的 `/data/3rdlibs/vcpkg`
- `mskdsp-vcpkg-cache`：`vcpkg` 下载与二进制缓存
- `mskdsp-ccache`：编译缓存

## 3. 启动长期驻留容器

```bash
docker run -d --name mskdsp-dev \
  -w /data/code/mskdsp \
  -v /home/code/share:/data \
  -v mskdsp-codex-home:/root/.codex \
  -v /home/code/.codex:/codex-sync:ro \
  -v mskdsp-vcpkg-root:/data/3rdlibs/vcpkg \
  -v mskdsp-vcpkg-cache:/root/.cache/vcpkg \
  -v mskdsp-ccache:/root/.cache/ccache \
  mskdsp-dev:ubuntu24.04
```

镜像入口会先执行 `script/devcontainer/init_vcpkg.sh` 固化的启动逻辑：

- 读取仓库 `vcpkg-configuration.json` 中的 baseline
- 校验 `/data/3rdlibs/vcpkg` 是否已命中该 baseline，且 `./vcpkg version` 可用
- 首次启动时自动 clone 并执行 `bootstrap-vcpkg.sh -disableMetrics`
- baseline 变化或目录状态异常时自动重建
- baseline 未变化时只做快速校验并直接复用
- 首次初始化后会基于 `scripts/vcpkg-tool-metadata.txt` 构建一个本地修补版 `vcpkg-tool`，规避容器环境下已复现的 `metrics.cpp` 负耗时崩溃
- 会将宿主机 `/home/code/.codex` 中的 `config.toml`、`AGENTS.md`、`skills/` 接到容器私有 `/root/.codex` 下，并把 `auth.json` 同步到容器本地

容器常驻命令仍为 `sleep infinity`，后续统一通过 `docker exec` 进入。

进入容器 shell 时，镜像会自动清理基础 devcontainer 镜像继承的全局 `CC/CXX`，避免 `openssl:arm64-linux-dynamic` 等交叉编译步骤错误拿到宿主侧 `gcc/g++`。

## 4. 进入容器与执行配置

进入交互 shell：

```bash
docker exec -it mskdsp-dev bash
```

也可以直接从宿主机执行单条命令：

```bash
docker exec -it mskdsp-dev bash -lc 'cmake --preset x64'
docker exec -it mskdsp-dev bash -lc 'cmake --preset arm64'
```

推荐在容器内串行执行：

```bash
cmake --preset x64
cmake --preset arm64
```

说明：

- 请串行执行，不要并行触发两个 preset，避免 `vcpkg` 锁竞争
- Codex 默认继续直接在 WSL 仓库路径中读写代码
- 需要编译或安装依赖时再进入 `mskdsp-dev`

如果之前已经创建过旧版 `mskdsp-dev`，升级到当前方案时需要重建一次容器：

```bash
bash script/devcontainer/start_mskdsp_dev.sh --recreate
```

如果宿主机 `.codex` 已被旧容器写成 `root:root`，先在宿主机修正属主：

```bash
sudo chown -R code:code /home/code/.codex
```

## 5. VSCode 使用方式

VSCode 推荐流程：

- `F1 -> Dev Containers: Attach to Running Container... -> mskdsp-dev`

不建议把 `Reopen in Container` 作为主流程，避免 VSCode 依据 `.devcontainer/devcontainer.json` 再创建新的 devcontainer 实例。

## 6. 与 CI 的对齐关系

开发容器的 `vcpkg` 初始化逻辑与 CI 保持同一原则：

- 从仓库 `vcpkg-configuration.json` 读取 baseline
- clone `https://github.com/microsoft/vcpkg.git`
- checkout 到 baseline
- 执行 `bootstrap-vcpkg.sh -disableMetrics`

在此基础上，开发容器会额外对 `vcpkg-tool` 做一次本地源码修补并覆盖到容器专用卷中。
原因：当前 WSL + Docker Desktop 环境里，官方 `vcpkg-tool` 在源码下载成功后仍可能因负耗时统计触发 `metrics.cpp` 崩溃；该修补只作用于开发容器，不修改仓库业务代码与 `vcpkg` baseline。
