# 平台点表获取与更新

## 已确认目标与边界

上位机的 Modbus RTU/TCP 模板目录及内容统一来自平台，移除运行时内置模板、个人模板库及本地模板导入入口。现场手动维护点位的能力保留。平台继续通过网页维护模板；上位机仅获取和应用，不授予网页管理权限。本次不部署、不修改真机或远端运行环境。

登录平台即可查询模板目录及版本；连接下位机后，读取实际点表和应用记录，才能比较现场差异。打开模板窗口时自动检查新版，提供显式刷新。缓存仅保存平台获取的数据，按平台隔离，标明缓存和版本，不绕过现有登录限制。无有效平台模板时显示空状态或错误，不恢复内置目录。

## 平台接口与历史

新增 `mskdsp.platform.templates.v1.TemplateCatalog` 只读 gRPC 服务，复用上位机 Bearer 会话认证。`ListTemplates` 返回目录摘要；`GetTemplate` 返回平台记录 ID、十进制字符串版本、完整原始模板 JSON 和时间。请求可指定历史版本，空版本表示当前版本。摘要与内容从同一数据库记录读取，防止版本和内容错配。JSON 上限 10 MiB、点位上限 10000，gRPC 接收上限考虑封装开销，拒绝越界与非法内容。

SQLite 在同一事务内维护当前记录及不可变历史快照。已有模板首次迁移时保留当前版本，之后创建、修改、删除、恢复均保留对应版本信息。删除整张模板不影响设备上的已有配置；历史查询需保持会话鉴权，不得将删除模板重新显示为当前可选模板。点位 ID 是稳定身份，编辑地址或名称时不得自动重建 ID。

## 下位机协议与原子保存

RTU/TCP 的 `PointTable` 增加 `uint64 revision = 3` 和 `string template_bindings_json = 4`。新下位机返回正数版本，旧下位机缺省版本为 0，上位机应明确提示不支持来源记录和并发保护，禁止降级为无来源模板应用。

`UpsertPointTableRequest` 增加 `optional uint64 expected_revision = 4` 和 `optional string template_bindings_json = 5`。不提供来源字段表示保留原记录；提供表示连同本次点表原子替换来源记录。模板应用必须为完整替换并携带预期版本与来源字段。比较失败返回 ABORTED，点表和来源保持原状；参数错误返回 INVALID_ARGUMENT；持久化失败不得推进版本或来源。

为保护连接配置并发，`UpsertLinkRequest` 增加 `LinkConfig expected_config = 3`，`UpsertPointTableRequest` 增加 `LinkConfig expected_link_config = 6`；字段存在时在同一互斥区完整比较配置，不一致返回 ABORTED。读取计划失败回滚同样携带预期配置，不能覆盖别人随后提交的串口、从站地址或读取计划。点表和来源先持久化，再同步 DataCenter 标签；磁盘失败不得先删除标签和路由，标签同步失败应回滚磁盘且明确报告回滚结果。

`UpsertLinkRequest` 同时增加 `optional uint64 expected_point_table_revision = 4`，读取计划扩展和回滚均携带本次应用初始点表版本。在点表已保存但响应丢失、或其他用户已更新点表时，旧版本配置回滚必须被拒绝，以免新点表使用旧读取计划。遇到响应丢失应明确提示重新读取确认保存结果，不能假称点表未生效。

来源记录是有界 UTF-8 JSON，结构为 `{schema_version:1, applications:[...]}`。每个应用记录携带独立应用 ID、平台身份、平台模板 ID、模板版本/快照、标签前缀以及源点位 ID 到目标标签、应用时实际点配置的映射。允许同一模板用不同前缀应用多次。每个映射保存自己的应用基线；跳过或保留现场值时不假称该点已更新。普通现场编辑保留来源基线，便于以后识别现场修改。连接重命名、模块配置持久化和恢复需保留版本及来源记录。

上位机 JavaScript 中所有 uint64 版本以十进制字符串传递，避免超过安全整数后发生错误比较。

## 更新规则

以应用基线、当前实际点表、平台最新模板进行三方比较，按稳定源点位 ID 关联，不按可变标签/地址猜测。未改动点的模板修改默认选中；现场改过的点标记冲突并默认保留现场值；新增点展示供选择，写点和条件点仍默认不选；平台删除点默认保留，只有明确勾选才移除。现场独立点不纳入模板删除。平台模板被删除时仅提示，禁止清空设备点表。

用户可查看修改字段、选择保留现场值或采用平台值。只推进已确认应用点的基线；未处理差异仍应可再次展示。应用前重读地址基准、实际点表、来源及版本，变化时中止并重新预览；最终保存由下位机版本比较兜底。保持原有链路内轮询功能的停止/运行状态，RTU 批量读取区间按新点表补齐，失败按原有流程回滚。只有点表和来源持久化成功才显示应用成功。

差异比较遵循下位机实际规范化语义：十进制按 Decimal20 的 20 位小数和半数远离零舍入精确比较，不能用浮点数替代；倍率零视为一，BOOL 忽略工程参数，字节序、字序及寄存器数的缺省按功能码和类型解释。现场重命名时原子更新映射的当前目标标签，但应用基线仍保留旧标签，用于识别现场修改。

上位机提供固定目标上下文和单次模板应用命令，使用运行目标代次及不可变连接快照。预览后的设备切换使提交失效；已经暂停的原设备只允许通过原快照善后，禁止从当前全局设备连接重新取通道。停止、读取计划配置 CAS、点表 CAS、必要回滚和恢复全部在同一目标事务内完成。

## 验收与测试顺序

先增加失败测试再实现：平台 Bearer 权限、目录/历史读取、历史迁移、事务回滚、删除模板；下位机协议字段、版本比较、来源校验、持久化/恢复、失败回滚及旧客户端兼容；上位机无内置目录、平台隔离缓存、三方差异、名称/地址变动、部分更新、默认保留删除和冲突、预览后并发修改、RTU/TCP 保存及旧下位机拒绝。

使用本机可用的 Rust、Node 和 Python 检查，执行上位机构建及相关回归。本机不具备下位机 C++ 编译环境，记录未运行的 C++ 用例；未经追加确认不连接服务器或真机编译部署。跨仓库协议先提交共享仓库，再更新消费者引用，仅提交本任务改动。
