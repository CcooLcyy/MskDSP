# Modbus 平台模板来源保存接口

RTU 与 TCP 点表读取返回正数 `revision` 和原样来源 JSON。新连接、旧格式恢复的点表初始版本为 1；每次成功保存递增，包含旧客户端未携带版本的保存。达到 uint64 上限拒绝写入。

点表写入可携带 `expected_revision`，不匹配返回 ABORTED。携带 `template_bindings_json` 时必须完整替换并提供正数预期版本；省略来源字段则保留既有来源，空字符串可清除来源。非空来源必须是 UTF-8 JSON 对象、`schema_version=1`、`applications` 数组，大小最多 32 MiB，应用与映射身份不得重复。手工删除或改名点位可暂时留下既有基线，用于上位机后续识别现场改动。

普通点位改名时，上位机可通过 CAS 同步 `mapping.target_tag`，应用基线的 `baseline.tag` 保留原标签，二者允许不同以识别现场改名；两者必须分别为合法非空标签。源快照 `source_snapshot.id` 仍必须与 `source_point_id` 一致。

版本比较、候选点表构造和持久化受同一互斥锁保护。先持久化候选点表和来源，再同步 DataCenter 标签，二者成功后才提交内存。磁盘保存失败不调用标签同步，避免标签替换提前清理路由；标签同步失败回滚磁盘原点表，内存版本及来源不推进，磁盘回滚失败明确返回错误并记录日志。RTU 所有整表快照写入另外按操作串行化，避免旧快照覆盖刚成功的 CAS。

携带来源时，同一锁内校验各应用记录的 `address_base` 与当前连接一致，变化返回 ABORTED，防止预览后地址基准变化而点表版本未变的并发窗口。

`UpsertLinkRequest.expected_config=3` 为可选完整连接配置 CAS，目标不存在或配置变化均返回 ABORTED；用于模板应用补齐读取区间及失败后恢复原配置，防止回滚覆盖其他客户端配置。`UpsertPointTableRequest.expected_link_config=6` 在点表保存同一锁内比较完整配置，不一致返回 ABORTED。未携带这两个消息字段的旧客户端仍保持原有调用方式。

`UpsertLinkRequest.expected_point_table_revision=4` 为可选点表版本 CAS，在保存连接配置的同一锁内比较当前正数点表版本；版本不符或目标不存在返回 ABORTED。模板应用扩展读取计划及失败后回滚时都携带初始点表版本，避免点表实际已提交但响应丢失时，回滚旧读取计划覆盖新点位需求。ConfigPusher 导入会清除源设备这一版本字段，旧客户端省略时兼容原调用方式。

持久化、恢复、连接改名及点表读取必须保留来源和版本，空点表也保留元数据。保存不自动启动链路内轮询功能，保持调用前停止状态。上位机更新成功后按原流程恢复先前运行状态。

配置导出应保留来源，但不得将源设备的 `expected_revision` 直接用于另一设备。ConfigPusher 导入携带来源的配置时，先读取目标设备点表版本，再以目标版本保存；旧下位机返回零版本时明确拒绝导入来源，避免静默丢失关联。无来源配置继续兼容旧流程。Modbus 控制面服务与 ConfigPusher 客户端消息上限均为 64 MiB。

验收采用协议字段契约与源码顺序检查、RTU/TCP 的 GTest 用例验证 CAS 冲突、旧客户端来源保留、持久化失败不推进版本及恢复/改名。当前 Windows 无下位机编译工具链，本次不搭建环境、不连接远端，C++ 用例留待可用环境运行。
