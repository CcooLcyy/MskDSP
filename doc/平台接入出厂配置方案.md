# 平台接入出厂配置

## 工作流与范围

平台固定为 `60.208.15.90:50000`，统一明文 gRPC，不提供地址、TLS 或证书编辑入口。设备发往现场前，上位机通过现场直连管理地址配置接入开关、设备 ID、设备令牌以及 SSH 开关和本机端口；保存后立即应用。下位机断电、重启、网络中断恢复和软件升级后，自动使用已保存配置接入平台。业务模块配置仍由 ConfigPusher 管理。

配置保存在下位机 `./conf/platform_access.json`，实际容器路径 `/opt/mskdsp/conf/platform_access.json` 对应已有宿主机持久目录。令牌必须由设备保存，但不进入上位机工作区、普通导出或日志；读取接口只返回 `token_configured`。文件使用 0600 权限、同目录临时文件、写入同步与原子替换。禁止跟随配置文件符号链接；缺少文件按未配置处理，损坏文件报告错误并保持接入关闭，不回退到环境变量启用。平台地址不从文件或环境变量覆盖。

## 管理协议

在现有 `ModuleManagerProto.ModuleManage` 管理服务增加两个幂等的一元 RPC，复用现场管理连接，不新增监听端口：

- `GetPlatformAccessConfig(Empty) -> PlatformAccessStatus`：读取脱敏配置与连接状态，不产生落盘或连接副作用。
- `SetPlatformAccessConfig(SetPlatformAccessConfigRequest) -> PlatformAccessStatus`：校验配置修订、原子保存后应用连接功能；相同内容可以重复保存。上位机仅在直连模式开放此操作，离线工作区禁止操作真实设备。

`PlatformAccessStatus` 字段：`enabled=1`、只读固定 `platform_target=2`、`device_id=3`、`token_configured=4`、`ssh_enabled=5`、`ssh_port=6`、`revision=7`、`online=8`、`last_error=9`。

`SetPlatformAccessConfigRequest` 字段：`expected_revision=1`、`enabled=2`、`device_id=3`、只写 `device_token=4`、`ssh_enabled=5`、`ssh_port=6`、`clear_device_token=7`。

- 首次配置修订为 0。过期修订返回 `ABORTED`，不覆盖他人已保存的配置。
- 空令牌表示保留已有令牌；`clear_device_token=true` 表示清除，与非空新令牌互斥。更换已配令牌的设备 ID 时必须提供新令牌或显式清除，不能误用旧设备身份。
- 开启接入必须具有合法设备 ID 与令牌。ID 限制为 1～128 个字母、数字、点、下划线或连字符；令牌最多 4096 字节且只能包含可见 ASCII。关闭接入允许尚未填写身份。未配置时平台接入仍关闭，允许远程 SSH 默认开启，本机 SSH 端口默认 10022；已有配置明确保存的开关、端口保持不变。SSH 端口为 1～65535，0 按默认 10022 处理；环境变量未指定 SSH 开关、端口时使用相同默认值，显式指定时以环境变量为准。
- 校验错误返回 `INVALID_ARGUMENT`，持久化或加载错误明确返回/展示，未安装控制器返回 `UNAVAILABLE`。旧版本缺少 RPC 时，上位机明确提示升级下位机。
- 保存响应不承诺设备已经上线。上位机显示已持久保存、正在连接、在线或脱敏错误；网络不可达时后台自动重试。

## 生命周期与实现边界

主进程拥有平台接入控制器，ModuleManager 仅注入窄控制接口，不反向链接 PlatformAgent。控制器启动读取持久配置；保存后切换连接任务，旧连接、隧道先取消回收，再使用新修订建立连接。不得持锁等待旧任务退出，旧修订的回调不得覆盖新配置状态。禁用后终止连接任务；开关不依赖业务模块是否启动。

上位机配置卡固定显示平台地址，不回填令牌明文；空输入保留，成功后清空新令牌输入。请求绑定现场连接代次，切换设备、地址或直连/远程模式后，旧响应不得回写当前页面。日志仅记录修订、设备 ID、开关与结果，禁止打印配置请求正文、文件内容或令牌。

现有升级启动脚本保留宿主机 conf 目录，仅替换模块启动策略。本轮增加行为回归验证平台接入文件内容及权限在升级重建后保留，不依赖 docker 环境参数传递。

## 验收

先补行为测试再实现：协议字段与旧接口兼容；脱敏读取；身份、端口与修订校验；原子写入失败；文件权限与符号链接拒绝；重建控制器恢复保存配置；禁用及重新启用；旧任务取消和旧状态隔离；升级保留配置；上位机仅直连可操作、旧设备响应隔离、空令牌保留及错误反馈。

使用随机端口假平台和独立临时目录验证，不向固定公网平台发起测试连接，不修改已运行设备、账号、授权或部署配置。提交后核对 GitLab 构建与测试，模拟 ARM64 结果与真实设备现场验收分别记录。
