# 设备普通外网出口配置

## 已确认的需求与边界

设备平台接入配置抽屉增加普通外网出口参数，复用现有“保存并应用”，不增加应用按钮。配置影响整个设备的普通 IPv4 外网流量，与平台接入启停独立；纵密地址、107/108 链路和 NAT 继续由纵密页面维护。本次开发不自动部署或改动现场设备。

现场示例为出口 `eth0.102`、网关 `192.168.2.1`、DNS `192.168.2.1`。地址均为配置值，不写死为现场默认行为。保留现有系统网络为兼容默认；选择指定出口后必须填写有效网卡、同网段 IPv4 网关，可配置 IPv4 DNS。

## 接口与持久化

ModuleManager 的既有平台接入读写接口增加可选 `OrdinaryNetworkConfig network_config`。字段为 `interface_name`、`gateway`、`dns_servers`；网卡为空表示使用系统现有网络。旧客户端省略消息时保留已有网络配置。新服务端始终回传消息以声明支持；旧服务端没有此字段时，上位机禁止提交新的网络设置，避免静默忽略。

状态额外回传 `network_applied`、`network_error` 和 `network_source_address`。网络应用失败必须与平台连接错误区分，不显示“配置已保存并应用”。配置沿用下位机 `conf/platform_access.json` 的原子写入、修订控制和持久卷；旧文件缺少网络字段时按系统现有网络加载。平台关闭时仍可保存并恢复网络出口。

## 路由与 DNS

普通外网配置只维护本功能拥有的路由表与策略规则，不清空主路由表、不删除其他默认路由、不修改 PPP 拨号程序。先保留主表中的直连和专用路由，再将其余 IPv4 目标送往指定网关，因此 PPP 的默认路由不会覆盖普通出口。已有纵密对端主机路由继续优先。

纵密脚本负责为 107 入站转发维护独立 PPP 路由表；PPP 未建立时不可回落到普通出口。PPP 恢复后更新自己的规则，与普通出口设置互不清理。现有双向 NAT 与现场地址配置保持原职责。

DNS 通过宿主机 systemd-resolved 的逐接口配置管理；首次修改前记录该接口原值，撤销时恢复。本功能不能覆盖其他接口的 DNS。宿主机总线或必要工具缺失时明确失败，不能仅保存后假报成功。容器发布需包含网络工具及 resolved 客户端，并连接宿主机系统总线；不自动修改当前运行容器。

容器在宿主机总线 socket 和 resolved stub 均存在时使用 `--dns 127.0.0.53`，确保容器内程序通过共享网络空间访问宿主解析器；缺少条件时保留旧部署行为。更新预检及失败回退分别兼容原部署和此精确参数组合，不放行任意自定义总线挂载或 DNS。

网络执行使用独立运行适配器，不将系统命令混入平台传输类；命令以参数数组执行，不拼接用户输入到 shell。配置应用、撤销和失败回滚均只操作本功能拥有的资源。平台地址、令牌、SSH 行为与纵密维护通路保持现有约束。

## 验收标准与测试顺序

1. 先补上位机控制器、Rust DTO、下位机配置和运行适配器的失败用例，再实现。
2. 同一个保存按钮提交平台与网络配置；回读不丢草稿；平台关闭不撤销普通出口。
3. 旧文件和旧请求兼容；旧服务端明确提示不支持网络设置；非法网卡、地址、DNS 和过期修订不改变配置。
4. 网络命令失败、持久化失败和重启恢复有明确状态；保留原配置或报告回滚失败，不伪装成功。
5. 命令桩验证普通路由保留专用主机路由、PPP 默认路由不抢占、107 入站不回落到 684；不在测试中修改真实网络。
6. 检查 DNS 逐接口恢复、重复应用幂等、切换接口及 PPP 重拨；纵密 NAT 原有测试继续通过。
7. 本地执行可用的工作流测试、Python 单元测试、前端构建与 Rust 检查；下位机缺少本地编译环境时明确报告，不擅自使用设备或远端构建。源码及命令桩验证不等同现场双卡联调。

## 使用顺序与实现说明

1. 更新包含本功能的下位机镜像和上位机。旧下位机仍可保存原有平台配置，但网络区域提示不支持，不能静默忽略新设置。
2. 在设备平台接入抽屉选择“指定网口和网关”，选择现场网口并填写网关与可选 DNS，使用原有“保存并应用”。选择“使用系统现有网络”会撤销本功能拥有的策略，并恢复所记录的逐接口 DNS，不清理其他功能的路由。
3. 纵密链路仍在纵密页面填写现场地址并应用。新版纵密脚本维护 107 入站专表 `18685`、优先级 `19900` 和双向 FORWARD 放行；PPP 未就绪时使用不可达默认路由。既有纵密配置需要重新应用新版脚本才具备这些规则。
4. 普通外网使用表 `18684`、优先级 `20000/20010`、自有资源协议标记 `242`，不修改 PPP 拨号程序。网关必须处于所选网口 IPv4 子网内，不能是本机、子网或广播地址。
5. 网络应用状态与平台在线状态分别展示；“配置已应用”不表示公网连通、运营商回程或纵密业务已经验证。失败须读取网络错误，恢复环境后重试，不能只凭保存提示判断成功。
