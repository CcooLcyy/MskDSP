# 控制前置编排实现方案

## 目标

对任意控制来源提供统一的前置控制流程。典型流程是：控制来源提交有功遥调值后，先下发遥控合，按需等待遥信点达到期望状态，再下发原遥调值。

控制来源不限定为 IEC104，也可以是其他协议模块、控制模块或上位机调用方。

## 职责边界

```text
控制来源 -> DataCenter -> ControlOrchestrator
                              | 前置命令
                              | 状态检查/轮询
                              v
                         DataCenter -> 实际目标模块
```

- DataCenter 仅依据已配置的源端点到目的端点路由转发同步命令，不判断业务策略。
- ControlOrchestrator 保存触发源点与编排的绑定，执行前置命令、状态检查、失败处理和原值透传。
- 上位机提供编排配置界面。保存绑定时自动注册 ControlOrchestrator 连接/标签并维护 DataCenter 路由，不要求用户手工进入数据总线页面配置。
- 编排步骤仍配置实际目标点；当编排配置了 `trigger` 时，上位机为每个步骤生成唯一的 ControlOrchestrator 内部输出点，并自动维护“内部输出点 -> 实际目标点”的路由。内部路由属于编排实现细节，不在数据总线路由配置页面展示或提供删除操作。
- 上位机中的触发源、步骤命令源和遥信状态源，统一从 DataCenter 已注册的连接与 `ConnTags` 级联选择，不允许新建配置时手工输入不存在的模块、连接或点名；编辑时若历史端点已失效，必须重新选择已注册端点后才能保存。
- 未绑定编排的源点保持原有 DataCenter 直达路径。

## 配置模型

一个编排包含：

- `trigger`：可选的触发源端点。配置后，发往该源点的同步命令由 DataCenter 路由到 ControlOrchestrator。
- `steps`：按顺序执行的命令步骤。步骤值可以是固定值，也可以透传触发命令值。
- `verification`：步骤执行后的可选遥信确认条件，包括状态端点、期望 BOOL 值、总等待超时和轮询间隔。状态端点可填写稳定连接主键，运行时由 DataCenter 解析 `conn_id`；状态读取使用源端最新值，不要求额外业务路由。
- `failure_action`：状态检查超时后的处理方式。
  - `STOP`：停止编排，不下发后续步骤。
  - `RETRY_COMMAND`：重新执行当前步骤命令，达到最大重试次数后停止。
- `max_retries` 与 `retry_interval_ms`：仅在重试模式下生效。
  `max_retries` 最大为 100，避免错误配置导致编排长时间占用执行线程。

未配置 `verification` 时，当前步骤命令成功后直接继续后续步骤；未配置 `trigger` 时，仍可通过原 `ExecuteSequence` RPC 手工执行。

启用 `trigger` 后，该源点用于同步命令的路由必须唯一；原有直达目标路由应迁移为编排触发路由，否则 DataCenter 会按多路由返回歧义，不会猜测目标。步骤输出路由由上位机自动维护，用户不需要在数据总线页面重复配置。

## 执行语义

1. DataCenter 根据触发源点找到唯一 ControlOrchestrator 目的端点，并转发同步命令。
2. ControlOrchestrator 根据请求源端点查找触发绑定；没有绑定时返回明确失败，不猜测业务路由。
3. 执行步骤命令。命令执行失败时立即停止；状态检查失败按 `failure_action` 处理，且不得继续下发后续原控制命令。
4. 配置了遥信条件时，通过 DataCenter 最新值接口轮询状态，直到达到期望值或超时。
5. 条件满足后执行后续步骤，其中 `use_trigger_value=true` 的步骤使用最初触发值。
6. 编排内部步骤通过 ControlOrchestrator 内部输出点进入 DataCenter，再路由到步骤配置的实际目标点；内部输出点不能再次使用绑定的触发源点，避免递归进入自身。
7. 任一步失败都返回失败响应，并记录请求 ID、编排名称、步骤和失败原因。
   `ExecuteSequenceResponse.failed_command_status` 保留 DataCenter 的失败类别，供协议调用方区分超时、不可用、无路由和业务拒绝。

## 兼容性和验收标准

- 现有 `ExecuteSequence`、固定步骤和手工执行页面继续可用。
- 三种模式可配置并可测试：不检查直接继续、检查失败停止、检查失败重试前置命令。
- 成功路径中原遥调值只下发一次，且在前置条件满足后下发。
- 失败路径中不得下发原遥调值；重试次数和间隔遵守配置。
- DataCenter 核心路由算法无需增加业务判断。
