# DataCenter 多对一路由放开方案

## 目标

允许多个 IEC104 连接，或其他协议连接，配置到同一个 DataCenter 目标端点。上位机数据总线不再因为目标点已有入站路由而阻止新增路由；DataCenter 按输入请求在服务端的处理顺序逐条转发更新。

## 范围

- 普通遥信、遥测点允许多个源端点指向同一个目标端点。
- 遥控、遥调点同样允许多个源端点指向同一个目标端点。
- 单个 IEC104 连接内部同一 IOA 的选择-执行、确认和超时状态机保持现有语义，不在本方案中改动。
- 不新增求和、平均、主备优选、质量择优等聚合或仲裁规则。

## 运行语义

1. 每次 `Publish` 或 `BatchPublish` 在 DataCenter 服务端串行处理，并按处理顺序生成目标更新。
2. 同一目标端点的每条更新都进入订阅队列，目标模块按队列顺序逐条消费；不因目标端点相同而合并或去重。
3. `GetLatest` 对同一目标端点返回最后处理的一条更新，即后处理值覆盖先处理值。
4. 订阅队列仍遵循现有 best-effort 容量限制；队列满时允许丢弃最旧消息，并记录中文告警。该情况不承诺每条更新均送达。
5. 若多个客户端并发调用发布接口，“先后”以 DataCenter 获取服务端处理顺序为准，不以客户端发起时间或网络发送时间为准。
6. 多个源端点通过 `ExecuteCommand` 指向同一目标连接时，DataCenter 为该目标连接建立顺序队列；命令按 DataCenter 受理顺序逐条调用目标模块。不同目标连接之间不互相阻塞。
7. 命令排队等待期间若调用方取消或超过截止时间，该命令从队列中移除，后续命令继续处理；单个命令进入目标模块后的超时、拒绝和 IEC104 选择-执行语义保持原有规则。

## 配置与校验

- `DataCenter.UpsertRoutes` 不增加目标端点唯一性校验，允许不同源端点共同指向同一目标端点。
- 上位机 DataBus 保留自环、重复路由和双向路由检查；移除多对一状态及其提交拦截。
- 自定义映射和一对一批量配对均可生成多对一路由；目标标签选择不再因已有入站路由而禁用。

## 测试与验收

- DataCenter 核心测试验证两个不同源端点指向同一目标端点时，两个 `PointUpdate` 均生成并按发布处理顺序返回。
- DataCenter 核心测试验证同一目标端点的 `GetLatest` 返回最后处理的源更新。
- DataCenter gRPC 测试验证多个源端点对同一目标连接执行同步命令时，第二条命令需等待第一条完成，不会并发进入目标模块。
- 上位机测试或静态校验验证 DataBus 不再产生或拦截 `manyToOne` 状态，并允许重复选择目标标签。
- 不改变单个 IEC104 连接内部的选择-执行命令状态机测试。
