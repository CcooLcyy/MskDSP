## 已确认目标与现场证据

普通 IPv4 外网继续通过 102 口与 684 网关；纵密流量继续由纵密功能独立维护。用户已确认将设备实测有效的 networkd 兼容配置纳入代码，不增加上位机按钮或修改配置来源。

2026-11-04 现场捕获：恢复 20000/20010 后 ping 立即成功，USB 蜂窝接口重建时两条规则删除；表 18684 的路由仍在。宿主机设置 `[Network] ManageForeignRoutingPolicyRules=no` 并重启 networkd 后，连续 150 包全部收到、31 次路由采样正常，蜂窝接口重建不再清除出口规则。修改前状态与证据保存在设备 `/var/backups/mskdsp-routing-20261104T094326`。该实验未验证 PPP 业务，也未修复蜂窝模块本身重连。

## 安装与升级边界

自解压安装器在镜像身份、载荷验证完成后，替换业务容器之前，幂等准备宿主机 networkd 兼容配置。配置路径沿用 `/etc/systemd/networkd.conf.d/60-mskdsp-routing.conf`，只设置 `ManageForeignRoutingPolicyRules=no`，不关闭外来路由清理，不修改网卡地址、DNS、纵密参数或 PPP 程序。无运行中的 networkd 时明确记录不适用，不擅自启动网络管理服务。

systemd 249 的 reload 不重读全局配置；第一次实际生效必须重启 networkd。该操作影响所有受管接口，须备份并恢复原有运行时 IPv4 地址、外加路由和策略规则，防止现场维护地址被清理。已完成兼容准备的升级不得重复重启。失败应明确中止安装，尽力恢复原配置与网络状态，保留诊断材料，不能先删除旧业务容器。宿主机设置作用于全设备的外部策略规则，各功能继续只清理自有资源。

## 运行时状态检查与恢复

运行适配器增加只读检查，复用现有 JSON 结果字段 `applied/error/source_address`；新增 C++ `CheckOrdinaryNetwork(config)`，不改变 protobuf。检查覆盖保存状态与待恢复事务、接口源地址、20000/20010 精确匹配、18684 网关与默认路由，以及显式指定时的逐接口 DNS。没有管理配置且没有残留状态时不依赖网络工具。

相同配置再次应用时，健康状态不写入路由或 DNS；缺失自有规则或路由时仅补齐缺失项，不先删除现有资源，不修改主表、PPP 表 18685 或纵密规则 19900。遇到外部优先级冲突、专表外部资源或状态不一致时明确失败，不覆盖。配置切换、撤销和待恢复事务继续沿用原事务与回滚流程。

Supervisor 每五秒核验运行状态，健康时不重启平台连接任务；失效时及时报告并尝试恢复，不改配置修订、不重复保存令牌。Get 返回实际检查结果；相同配置 Set 不再仅凭缓存跳过修复。检查和保存串行化，避免旧配置的检查或恢复覆盖新配置。错误与恢复只在状态变化时记录，避免健康检查刷日志。

Get 在网络事务繁忙时立即明确返回未核验状态，空闲检查总时限为六秒。Set 最多等待事务锁一秒；繁忙时返回 `UNAVAILABLE` 并说明本次未保存，不进入排队长等待。检查、应用及失败恢复的组合预算约四十三秒，保持在上位机现有四十五秒写入时限内。上位机沿用现有错误处理，不增加自动重试或新按钮。

## 验收与验证范围

先增加失败用例，再实现：规则删除、单条缺失、路由缺失、DNS 偏离、健康重复应用无写操作、外部冲突不覆盖、相同保存修复、平台关闭仍恢复、周期核验不重启健康平台任务，以及安装准备幂等、失败回退与旧业务容器保护。所有本地网络命令使用隔离桩，不访问本机网络。

执行 Python 事务/安装器/更新任务测试、相关上位机工作流契约测试和可用静态检查；新增 C++ 用例由下位机 CI 编译执行，本机不搭建缺失的 Linux 构建环境。本次实现不自动再次部署真机；上次设备实验不能替代新安装流程与完整双卡业务验证。

## 本地实现验证

- 网络事务 34 项、宿主机准备器 11 项在 WSL 全部通过；Windows 跳过一项依赖 POSIX flock 的事务锁用例。
- 安装器 35 项、更新任务 55 项在 WSL 全部通过；上位机平台配置及嵌入更新器契约 14 项通过。
- 独立 Linux user/net namespace 中使用原生 ip 命令验证附加 IPv4 地址、主机路由、专表默认路由和缺失策略规则恢复，重复恢复无重复规则；验证真实应用、只读检查、规则丢失检测、增量修复及健康重复应用。
- 原生验证发现并修复两类命令桩未覆盖的问题：`ip route restore` 需要可 seek 的文件输入；iproute2 JSON 的 `suppress_prefixlen` 别名及 scope/type 数字字符串需要规范化。已增加对应回归，不能仅凭命令退出成功报告应用成功。
- 新增四个 Supervisor 行为用例，覆盖真实状态、相同保存修复、读取不等待慢应用、周期维护保持连接以及保存等待上限。本机不执行下位机 C++ 编译，交由 CI 编译运行。
- 网络 Python 与安装/更新回归加入独立 CI 作业，两个架构的打包均依赖该作业成功；GitLab CI 配置校验有效且无警告。clang-format、脚本语法及差异检查通过。
