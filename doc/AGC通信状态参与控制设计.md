# AGC 通信状态参与控制

## 已确认需求与边界

- 协议模块使用 DataCenter 现有点注册、发布和路由接口提供连接通信状态；第一期实现 ModbusRTU（含 MQTT 串口透传），其他模块可复用同一约定。
- AGC 成员配置的“可控”属性保持不变。启用通信状态关联后，仅“可控且通信正常”的成员参与本轮目标分配；掉线、恢复均触发重新计算，无须等待新总目标。
- 不可控成员不参与目标分配。通信失败的可控成员退出分配、停止设点，剩余成员按原总目标和各自权重、容量及上下限重新分配；不扣除掉线成员的最后出力。
- 启用通信状态关联的组按上述参与集合计算量测、动态容量和分配，不将不可控成员的出力扣减总目标。完全未关联状态点的旧组继续保留原有被动出力口径，避免静默改变旧配置。
- 全部可控成员不可用时停止成员设点，报告无可调资源及未分配目标。容量不足时报告剩余差额，不突破成员约束。
- 不修改 AVC、设备协议写入逻辑和其他聊天正在开发的 AGC 增减闭锁、DataCenter 品质位逻辑；在其他任务提交稳定后集成 AGC 消费端。

## 统一发布约定

- 每条协议连接在自身 DataCenter conn_id 下注册保留系统标签 `__communication_state`，普通点表禁止占用此标签。
- 使用 UINT16 发布：0=未知，1=通信正常，2=通信异常，3=已停止。仅值 1 可允许参与控制；不依赖上位机在线。
- 正常、异常沿用协议模块真实通信判断；RTU 每轮至少一个点解析成功即正常，否则异常。此状态不保证全部点正常，也不代表控制写入成功。
- 创建、恢复和停止连接发布已停止；开始轮询前发布未知；每个完整轮询结束均发布当前状态，不受普通遥测死区过滤。停止必须在旧轮询退出后发布，防止旧正常状态覆盖。
- 同一状态持续发布作为心跳，接收端按源时间戳和本机接收时间检查过期；发布失败记录日志并在后续轮询重试，禁止因发布失败停止正常协议采集。
- 消费端不得把“量测值没有变化”判作失联。健康状态点独立于遥测数值变化。

## AGC 消费端与配置

- 成员新增可选通信状态输入和超时时间；未配置时兼容原控制行为。新配置通过选择已有协议连接的系统状态点建立 DataCenter 路由。
- 状态输入为 `MemberConfig.communication_state`，超时为 `communication_timeout_ms`；0 默认 30000 毫秒，非零允许 1000..3600000 毫秒。应按源连接完整抄读周期调大超时。
- 输入缺失、质量无效、值未知/异常/停止或心跳过期均不参与；过期必须由下位机定时检查，PI 事件模式也不能仅等待输入变化。
- 状态变化应作废旧计算与待发布设点；发布前再次核对参与资格，防止失联后继续发出旧目标。
- 恢复时按当前总目标重新分配，清理失联期间积分、旧成员目标和设点去重缓存，确保恢复后的首个有效设点实际发布。
- 周期直分配继续遵循已配置命令周期；失联成员停止下发立即生效，剩余成员按允许的下发时机发送重分配结果。
- 通信关联组对增量总命令按命令版本保存已解析的绝对总目标；通信变化与量测更新仅重分配该目标，不重复叠加增量。
- 自动调试开始前必须掌握全部可控成员的有效通信状态；调试中参与资格变化立即失败并清除候选参数，待通信恢复、停止任务清理后重新调试。
- 运行界面区分配置可控、通信状态、是否参与计算及退出原因；成员弹窗确认仅修改草稿，控制组最终保存才提交配置与路由。

## 验收场景

1. 三台等权、容量足够的在线可控设备，总目标 300 kW，各分配 100 kW；其中一台通信异常后其余两台各分配 150 kW，异常成员无设点。
2. 同一台恢复后，无新总命令也恢复为三台各 100 kW；不可控成员无论通信状态均不参与分配。
3. 未完成首轮、状态质量无效、心跳过期、连接停止或模块退出时不使用缓存正常状态继续控制。
4. 全部掉线不发布成员设点；剩余容量不足时约束有效并报告差额。
5. RTU 普通点值不变、死区过滤期间，健康状态持续刷新；点表替换、配置恢复均保留系统状态标签。
6. RTU 点读与显式块读都覆盖失败和恢复；停止后不出现旧正常状态覆盖；系统标签冲突被拒绝。
7. 未关联通信状态的既有 AGC 配置保持原行为；AGC 增减闭锁与通信参与资格同时成立后才允许对应控制。
