# 命令编排模块最小实现方案

## 目标

新增独立的 `ControlOrchestrator` 模块，提供协议无关的线性命令编排能力。典型场景是：逆变器遥调前先发送遥控合命令，前置命令成功后再发送遥调值。编排模块不解析 Modbus、DLT645 或 IEC104 报文，只通过 DataCenter 的同步命令接口调用目标协议模块。

## 第一版范围

- 支持多个命令编排，按名称持久化。
- 每个编排包含固定顺序的 1~8 个步骤。
- 每个步骤包含 DataCenter 命令源模块、源连接、源点、固定值或触发值、超时时间和步骤间延时；DataCenter 再按路由寻找协议模块的实际目的端点。
- 通过 gRPC 提供编排的新增/更新、查询、列表、删除和同步执行接口。
- 执行采用“前一步成功后执行下一步”的串行语义；任一步失败立即停止并返回失败步骤和原因。
- 同一编排使用互斥锁，避免并发执行交错写入。
- 配置由 ConfigPusher 通过 JSONC 下发，上位机提供配置和手工执行界面。

## 暂不实现

- 条件分支、循环、并行步骤和补偿/回退动作。
- 自动从所有 DataCenter Publish 流量中拦截命令。
- 协议模块内部的状态轮询确认；第一版以目标模块同步命令返回 `COMMAND_ACCEPTED` 作为步骤成功依据。
- AGC/AVC 自动输出和 IEC104 主站发送路径的自动改造；这些调用方后续可改为调用编排执行接口。

## 配置语义

每个编排配置一个稳定名称和步骤列表。步骤使用 DataCenter 稳定源端点（`module_name/conn_name/tag`），值支持 `BOOL/INT/DOUBLE/STRING/BYTES` 中的一种；`use_trigger_value=true` 时复用执行请求的值，适合“先合闸固定值，再下发原遥调值”。

编排执行请求指定 `sequence_name`、触发端点、触发值、请求 ID 和总超时。模块按步骤调用 DataCenter `ExecuteCommand`，为每一步生成关联请求 ID。配置校验阶段拒绝空名称、空步骤、重复步骤名、超出 8 步和非正超时。

## 失败与可观测性

- 目标模块不可用、超时或返回非 `COMMAND_ACCEPTED` 时，编排立即失败，不执行后续步骤。
- 响应返回最终状态、已执行步骤数、失败步骤序号和中文原因。
- 每个步骤记录目标、值、开始/结束和结果日志；配置错误、执行失败和 DataCenter 调用失败均写中文日志。
- 编排配置落盘失败时返回错误，内存配置不假装成功。

## 验收标准

1. ConfigPusher 能从 `control_orchestrator.jsonc` 下发配置并自动收敛模块中的旧编排。
2. 上位机能新增、编辑、删除、刷新编排，并手工执行一条编排。
3. 两步编排在模拟 DataCenter/目标模块下按顺序执行；第一步失败时第二步不执行。
4. 并发执行同一编排时不会交错，第二个请求在第一个完成后执行。
5. 非编排的现有协议命令行为保持不变。
