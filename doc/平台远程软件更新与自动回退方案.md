# 平台远程软件更新与自动回退

## 目标与授权范围

用户已确认实施单设备应用更新：复用平台 SSH 隧道；宿主机独立执行；安装或本地健康检查失败时自动回退；稳定状态最多保留一个先前版本。此次只修改与本地验证，不部署、不连接现场设备、不更新操作系统、不增加批量更新。

## 连接与身份

直连继续兼容原接口。远程请求追加 `remote_target: { endpoint, device_id }`，固定平台及设备身份，SSH 用户仍从 `upload_account` 提取，不能将随机本地隧道端口保存为设备身份。每次操作按固定设备建立 SSH 隧道，重新校验平台会话和 SSH 权限；不得因用户切换设备而发送到新设备。首次主机指纹必须明确确认，变化拒绝，复用远程终端的持久信任记录。远程更新第一版使用密码认证，界面应明确限制。

## 宿主机任务契约

上位机提供独立的提交与查询接口：`submitLowerUpdateTask`、`getLowerUpdateTask`。提交请求包含既有连接及安装参数、UUID `operation_id`、`package_sha256` 和 `expected_image_id`；查询包含连接参数及原任务编号。返回 `operation_id`、`phase`、`message`、`expected_image_id`、可选 `actual_image_id`、可选 `exit_code`、有界 `log_tail`。

任务阶段为 `accepted/preparing/installing/verifying/succeeded/rolling_back/rolled_back/rollback_failed/failed`。未收回执、SSH 断线或平台离线属于观测状态未知，不等于安装失败。重连必须查询同一个任务；相同编号、相同包摘要及镜像返回原任务，相同编号不同内容拒绝。宿主机全局互斥，只允许一个应用安装任务。`accepted` 的重试需要调和“记录已保存但 systemd 尚未接管”的窗口。

宿主机 Python helper 由上位机携带并通过 SSH 安装到 root 管理目录；源文件位于 `script/update/lower_update_task.py`，上位机维护字节相同的嵌入副本。运行前必须将 helper 和安装包复制到 root 独占目录并再次校验包摘要，不能让 root 长期执行普通用户可修改的脚本或包。任务目录、状态、日志均在业务容器外，状态原子写入，不保存平台令牌、SSH 或 sudo 密码。独立 systemd 任务执行安装，不依赖上位机、SSH 通道或业务容器存活。要求设备已有 Python 3.9 以上、systemd、Docker，缺少时在替换业务容器前拒绝。

## 安装、健康检查和回退

校验包摘要、架构、镜像身份、磁盘空间及可恢复的原部署后，先备份当前镜像身份、容器运行参数、宿主机 module 和 conf。配置目录中的 SQLite 数据库采用标准库在线 backup，使用有界等待，不将活跃 WAL/SHM 文件当普通配置分别复制。更新任务持有安装互斥锁；保留恢复材料后才调用安装包 `start`。安装包必须带受管理更新能力标记，不支持的旧包在预检拒绝；安装器受管理更新模式约束，不得提前清理恢复所需镜像。

新版本必须满足容器运行、期望镜像一致、管理服务环回端口 17000 可用，以及更新前已运行模块的 Unix socket 可连接。业务模块的随机 TCP 端口不作为稳定身份；从原容器中获取模块 socket 集合，在新容器中检查相同集合。此检查证明进程及接口基本就绪，不等同于采集、控制或协议业务验收。不以平台是否在线作为回退条件。本地健康检查使用有界等待，检查失败自动还原更新前镜像、配套 module、conf，并检查旧业务恢复。平台配置随 conf 保留，日志不回退。仅兼容当前安装器生成的可恢复部署，无法可靠重建的自定义部署应在变更前拒绝。第一版不承诺跨不兼容配置迁移和断电事务恢复。

稳定状态为当前版本 + 一个先前版本；准备新版本时允许临时存在候选版本。新版本验证成功后才轮换先前版本，不能在安装前删除唯一恢复材料。回退成功返回 `rolled_back`，回退失败返回 `rollback_failed` 并保留材料；不能将回退成功展示成升级成功。

## 上位机流程与恢复

远程模式明确显示固定设备，依次执行预检、上传及远端校验、保存任务编号、提交、查询。提交前本地持久保存无密码的任务记录；页面卸载不取消任务。上位机关闭后宿主机继续执行；重新打开提供恢复查询及重新输入认证信息的入口。等待重连使用有界轮询，超时展示“暂时无法确认”，不自动重装、不自动换任务编号。成功前不得执行旧包清理，回退材料由宿主机管理。

## Docker 默认部署预检兼容（2026-10-23）

x64 服务器默认安装器创建的容器在 Docker inspect 中带有 `SecurityOpt=["label=disable"]`，且 host 网络的默认 `Hostname` 等于宿主机名。旧预检将这两项误判为自定义配置，更新在业务替换前失败。

- 继续要求默认特权容器与 host 网络，只接受缺省、`null`、空列表或严格等于 `["label=disable"]` 的 `SecurityOpt`。其他安全选项及混合列表一律拒绝，不能泛化放开 seccomp、AppArmor 或其他定制参数。
- 主机名仅接受空值、原容器 ID 前 12 位或当前宿主机名；其他自定义主机名继续拒绝。宿主机名由实际执行 helper 的宿主机读取，不能从待检查容器反推。
- 安装与回退继续使用既有默认 Docker 参数，让 Docker 生成对应默认值；不添加安全选项或主机名覆盖，不改变网络、权限、挂载、镜像与健康检查策略。部署检查通过后在任务日志记录默认部署校验结果。
- 先补默认值与拒绝边界的失败测试，再同步上下位机 helper。验收覆盖默认组合、自定义安全选项/主机名拒绝、原有自定义配置拒绝、安装/回退参数及两份 helper 字节一致。

此修复由更新后的上位机携带并在新任务中分发；旧失败任务不会自动重跑。本次只修改源码及执行隔离测试、只读部署校验，不安装应用或重启现场容器。

验证结果：Windows helper 49 项通过、Linux 专用锁测试 1 项跳过；WSL Linux helper 50/50 通过，安装器隔离测试 27/27 通过，跨仓库字节一致性契约 1/1 通过。服务器实际 Docker inspect 数据通过修复后的部署检查，内存中附加安全选项与自定义主机名仍被拒绝，检查前后容器 ID、镜像及启动时间一致。只读部署校验不等于真实安装、回退或业务验收；未执行下位机 C++ 与上位机打包构建。

## 配置备份来源与可信执行路径分离（2026-10-29）

现场 `conf/configPusher` 为 root 所有的 0777 目录，旧助手把配置备份来源等同于 root 执行路径，在上传完成后的备份阶段拒绝整个更新。此次调整检查策略，不修改设备目录权限，不部署助手或安装应用。

- 更新助手、暂存包、任务状态、恢复材料和模块代码继续使用严格的可信路径检查；配置来源的放宽不能传播到这些路径。
- 普通配置子目录允许非 root 所有或组/其他用户可写，但只作为备份数据读取。读取必须绑定已核验的目录和文件，拒绝符号链接、特殊文件、越界及路径替换；备份结果保存在受保护目录，不把源目录的宽权限带入恢复材料。
- SQLite 保留在线一致备份与有界等待，不复制活跃 WAL/SHM 作为普通配置。数据库及相关文件的安全打开条件需要独立检查，不能直接复用允许普通配置可写的规则。
- `HOST_ROOT`、`conf` 根及完整父链继续要求 root 独占；只放宽 `conf` 内普通数据的属主与写权限。配置遍历以 `dir_fd`、`O_NOFOLLOW` 和打开前后对象身份核对绑定目录，拒绝软链接、硬链接、特殊文件及内容/路径变化。恢复材料仍为目录 0700、文件 0600；不修改来源权限，回退沿用原有收紧权限行为，不承诺还原来源的 0777 或非 root 属主。
- SQLite 会按路径重新打开主库和侧文件，因此主库、WAL/SHM/journal 及完整父链仍要求 root 独占。可写数据子目录中的 SQLite 明确拒绝；受保护数据库的活跃 WAL 提交允许继续，文件内容一致性由 SQLite 在线 backup 保证，不按普通文件的时间戳误判。目录名称变化仍安全拒绝。
- 上传前只读扫描业务目录，聚合可发现的权限、文件类型及链接问题；不创建目录、状态或日志，不改变权限。安装前重复校验并在配置复制发生变化时安全失败；尚未完成恢复材料前不得替换业务容器。
- 只读业务扫描最多 10000 项、10 秒，条目使用迭代读取，在枚举、元数据检查和文件头读取阶段持续检查时间，耗尽预算即终止；最多显示 50 条问题（每条 500 字符），超出时提示剩余数量。配置实际备份独立限制为 120 秒、10000 项；单个普通文件上限 4 GiB，复制过程中继续执行大小及时间限制，SQLite 备份前后也检查总预算。SQLite 在线 backup 保留原有 30 秒等待限制。
