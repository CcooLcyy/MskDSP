# IEC 61850 下位机实现方案

## 1. 文档状态

- 状态：实现基线
- 适用范围：MskDSP 下位机
- 模块名称：`IEC61850`
- 不包含：MskDSPUpper、MQTT、物管平台协议

本文档是 IEC 61850 下位机实现、测试和验收的依据。功能实现遵循“文档 -> 测试 -> 实现”的顺序。

### 1.1 当前实现进度

截至当前实现批次：

- SCL模型、MMS会话契约、报告分段与DataCenter异步管线已经形成协议无关实现。

- A/B通道、GOOSE订阅端点和SV流端点分别使用独立SPSC生产者，实时入口不调用DataCenter、gRPC或SQLite。
- 生产模块在未启用MMS时使用raw GOOSE/SV适配器；MMS已采用自研的ISO会话、Presentation、ACSE、BER、Initiate和InformationReport分层实现，在线目录、RCB配置、完整GI/READY闭环、多个RCB分别配置和A/B接管后的重新配置已形成基础链路。真实设备互操作、GOOSE/SV高负载和保护算法仍需现场验收，不能据此宣称全部IEC 61850能力已经完成。

## 2. 建设目标

在 MskDSP 中新增一个动态加载的 `IEC61850` 模块，在同一模块内提供以下能力：

1. 导入并校验 SCD/CID/ICD 模型。
2. 作为 IEC 61850 客户端连接下方 IED，完成 MMS 目录读取、数据读取、报告订阅和控制服务。
3. 通过二层网络接收和发送 GOOSE。
4. 通过二层网络接收 SV，对原始采样进行内部计算。
5. 在模块内部完成对时延敏感的 GOOSE 联锁、保护动作和 SV 计算。
6. 将遥信、遥测、品质、时标、事件及计算结果异步发布到 DataCenter。
7. 支持 A/B 网、断线重连、运行状态查询、统计与诊断。

## 5. 核心身份模型

### 5.1 IED 与 DataCenter

- `module_name` 固定为 `IEC61850`。
- 一个逻辑 IED 对应一个 DataCenter 连接。
- `conn_name` 使用配置中的 IED 别名，在 IEC61850 模块内唯一。
- `conn_id` 由 DataCenter 按 `(module_name, conn_name)` 分配并持久化。
- A/B 网络是同一个 IED 下的两个传输通道，不创建两套 DataCenter 连接和点表。

### 5.2 点身份

每个外部可见点至少包含：

- `tag`：DataCenter 使用的稳定点名。
- `data_ref`：IEC 61850 对象引用，例如 `IEDLD/LLN0.Mod.stVal`。
- `fc`：功能约束。
- `source`：`MMS`、`GOOSE`、`SV_DERIVED` 或 `INTERNAL`。
- `value_type`：布尔、整数、浮点、字符串或字节串。
- `scale/offset/deadband`：工程量转换和变化过滤参数；布尔点忽略。

导入时默认以规范化 `data_ref` 生成 `tag`，允许后续配置覆盖。`tag` 在一个 IED 内必须唯一，`data_ref + fc` 在一个 IED 内必须唯一。

## 6. SCL 模型要求

### 6.1 输入

- 支持 SCD、CID 和 ICD XML 文档。
- gRPC 导入接口接收文件内容和来源名称，不依赖调用方与模块共享文件路径。
- ConfigPusher 可从本地配置指定的文件读取内容后调用导入接口。
- 单个模型大小、完整目标态序列化消息大小和展开后的对象数量必须配置上限；数量等于上限允许通过，严格超过上限返回 `RESOURCE_EXHAUSTED`。

### 6.2 解析范围

必须解析并建立引用关系：

- `IED`、`AccessPoint`、`Server`、`LDevice`、`LN0`、`LN`。
- `DataObject`、`DataAttribute` 以及 `DataTypeTemplates`。
- `DataSet`、`FCDA`。
- `ReportControl`、`TrgOps`、`OptFields`、`RptEnabled`。
- `GSEControl`、`SampledValueControl`。
- `Communication/SubNetwork/ConnectedAP`。
- MMS IP、OSI 参数以及 GOOSE/SV 的 MAC、APPID、VLAN ID、VLAN优先级。
- `Inputs/ExtRef` 外部引用。

每个 `ExtRef` 至少规范化保存所属逻辑节点、内部地址、外部 `iedName/ldInst/prefix/lnClass/lnInst/doName/daName`、功能约束、服务类型和 `srcLDInst/srcPrefix/srcLNClass/srcLNInst/srcCBName`。当外部引用具备完整对象定位字段时，同时生成稳定的发布端 `data_ref`，供GOOSE/SV订阅配置和诊断使用。
GOOSE接收计划和本地发布计划必须分开编译。接收计划只来源于当前目标IED的 `ExtRef`，本地发布计划只来源于当前目标IED/AccessPoint的 `GSEControl`、对应 `DataSet` 和通信网段 `ConnectedAP/GSE`。保护规则的 `output_control_ref` 解析到发布计划编号，不能依赖接收订阅是否同时存在；只发布不接收的IED仍必须能够启动GOOSE发布功能。

所有位于 `AccessPoint/Server` 下的规范化对象必须保存所属 `access_point`，包括LN、DO、DA、DataSet、ReportControl、GSEControl、SampledValueControl和ExtRef。同一IED的不同AccessPoint可以出现相同对象引用，目录、控制块引用校验和点映射校验必须以当前IED配置选择的AccessPoint为边界，不能在不同AP之间互相满足引用。AccessPoint名称必须非空且在同一IED内唯一；启用协议功能的目标AccessPoint必须包含Server。

为兼容已有SQLite中的旧规范化模型，对象未携带 `access_point` 且IED只有一个包含Server的AP时，可将这些对象安全归入该AP；若IED存在多个包含Server的AP，旧对象归属不可推断，配置校验或启动IED通信功能必须明确拒绝并提示重新导入SCL，不能把多个Server模型合并后交给协议栈。

网络解析不能只筛选 `type="8-MMS"`；MMS、GOOSE 和 SMV 通信元素都必须纳入统一模型。

### 6.3 导入语义

- `validate_only=true`：只解析和校验，不修改当前配置。
- `replace=true`：以导入结果替换指定模型；运行中的相关 IED 不允许替换。
- 重复导入相同内容应具有幂等结果。
- 解析失败必须返回文件名、元素路径和可定位的错误原因。
- 持久化失败返回错误，不能启用未完整落盘的新模型。

## 8. MMS 数据面

### 8.1 能力顺序

1. 建立连接、Identify 和在线目录核对。
2. 读取数据集和 RCB 参数。
3. 启用 BRCB/URCB。
4. 支持 GI、周期完整性、`dchg`、`qchg`、`dupd`。
5. 处理 ConfRev、EntryID、序号和报告分段。
6. 断线检测、退避重连和 A/B 通道切换。
7. 遥控、设点、定值读写及协议级确认。

#### 8.1.1 MMS会话核对契约

本项目协议栈优先采用自研编解码实现，不直接复制或链接其他开源 IEC 61850 实现。MMS传输层、BER 编解码、ACSE 会话和 MMS 服务按独立适配层逐步实现；任何后续外部协议库只能作为可替换 Adapter，必须先完成许可证、目标架构和互操作性评估。

传输层先完成 ISO-on-TCP 的 TPKT/COTP 建链和有界分帧：每个 A/B 通道独立建立 TCP 会话，发送和接收均校验 TPKT 版本、长度、COTP PDU 类型及数据边界；超过单个TPDU上限的载荷按EOT分段发送，接收端只在最后一段重组完成后交给ACSE/MMS层，并限制单份重组载荷为4 MiB。一次 MMS 关联建立（TCP/COTP、Session CONNECT/ACCEPT）使用一份总的绝对截止时间，TCP连接、COTP确认和Session确认只能消费同一份剩余预算；不能因为进入下一层协议而重新获得完整超时。一次多分段发送或接收也使用同一份绝对截止时间，不能因为后续分段重新到达而重复获得完整的超时窗口。若完整非EOT段已经接收而后续段暂未到达，轮询超时保留重组前缀；若某个TPKT只收到半帧，必须关闭当前通道并重新建链，避免后续读取从半帧中间开始。MMS通道配置了网卡名时使用 `SO_BINDTODEVICE` 固定出口；未配置网卡名时使用系统路由，GOOSE/SV二层端点仍必须配置网卡。连接超时、部分读写、对端关闭、非法长度和非数据TPDU必须转换为带中文原因的协议错误；非法帧、半帧和重组上限错误会关闭当前MMS通道，不得把污染流交给 ACSE/MMS 层。

当前自研会话层优先实现IEC 61850常用的短Session/Presentation模式：CONNECT/ACCEPT使用CN/AC SPDU和短CP前缀，已建立关联后的请求使用DATA SPDU、短Token字段和P-DATA-TF；AARQ/AARE支持MMS application-context、结果/诊断以及EXTERNAL single-ASN1-type用户信息。解码器同时兼容旧设备常见的OCTET STRING用户信息，但不会放宽长度、OID、Context ID或嵌套TLV边界。会话层不依赖第三方ASN.1库，所有输出由调用方提供有界缓冲。

MMS建链的第一条应用PDU采用自研的 `InitiateRequest/InitiateResponse` 编解码器。请求和响应均限制为确定长度BER，严格检查 `localDetail`、并发服务数、数据结构嵌套层级、版本号、11位参数支持和85位服务支持位串；位串的未使用位数和末字节低位必须符合规范。Initiate PDU只在ISO关联完成后发送，未收到结果为接受且字段协商一致的响应前，不进入在线目录读取或 `READY` 状态。该编解码器不承担目录、报告或DataCenter逻辑，输出由会话工作器提供的固定上限缓冲承载。

BER 编解码器只支持本项目使用的确定长度TLV，长度字段、整数符号扩展、无符号范围、布尔值、OID和八位串均在写入和读取时做边界检查；收到无限长度、非规范整数、超长长度字段或嵌套范围越界时拒绝整个PDU。编解码器不分配网络线程专属对象，所有输出由调用方提供有界缓冲。

协议栈适配器建立MMS传输连接后，必须先用当前 `ProtocolIedPlan` 生成期望模型，再提交在线目录快照给协议无关的会话核对器。在线目录快照必须携带服务端 `IED + AccessPoint` 身份并与启动计划完全一致。在线目录允许包含配置之外的额外对象，但期望的逻辑节点、数据属性（`data_ref + fc`）、DataSet及其有序FCDA成员、ReportControl必须全部存在；同名对象不能用另一个AccessPoint的对象满足。缺少对象、DataSet成员数量或顺序不一致、数据属性FC不一致时，目录核对失败，IED不能进入 `READY`。

当前自研 `MmsSessionWorker` 已串接 TCP、COTP、Session、Presentation、ACSE、Initiate、在线目录、RCB配置、首次GI和InformationReport接收，并通过 `ProtocolStackAdapter` 上报完整A/B通道快照；建立MMS关联只允许报告 `CONNECTED`，目录、RCB和首次GI尚未完成前不得报告 `READY`。工作器不在收发线程中调用DataCenter、SQLite或gRPC，也不把未实现的MMS服务能力写入Initiate支持位。受控Read/Write请求通过通道内串行命令队列执行，调用方不能直接并发访问传输对象。DataCenter同步命令由独立的 `CommandExecutor` gRPC服务接收，先按点映射校验目标IED和FC=CO控制对象，再由工作器按在线ctlModel完成直控或SBO选择-执行。

#### 8.1.2 首批MMS服务编解码边界

首批服务层继续使用本项目自研的确定长度BER编解码，不引入ASN.1生成器或第三方MMS库。`Confirmed-RequestPDU`使用上下文标签`[0]`，`Confirmed-ResponsePDU`使用`[1]`，`Confirmed-ErrorPDU`使用`[2]`；三者内部先编码通用的`invokeID`。正常响应必须再编码确认服务选择，错误响应必须解析`ServiceError`的`ErrorClass`、附加错误码和描述。服务选择和服务体必须保持在同一份有界PDU中，响应或错误必须核对`invokeID`，不能把其他请求的响应交给当前请求。

第一批只开放以下服务：

- `GetNameList`（服务选择`[1]`）：支持`ObjectClass`基本类、VMD/Domain/AA三种对象范围和`continueAfter`；响应解析有序Identifier列表及`moreFollows`，并限制条目数、Identifier长度和整份PDU大小。
- `GetVariableAccessAttributes`（服务选择`[6]`）：首批支持按VMD、Domain或AA对象名发起请求。对象名使用标准的上下文选择和Domain内`domainId + itemId`顺序编码；响应解码为有界的TypeSpecification树，支持命名类型、数组、结构和常用基础类型，未知选择、递归过深、成员过多或位宽溢出时拒绝整份响应。
- `GetNamedVariableListAttributes`（服务选择`[12]`）：按DataSet对象名读取有序成员对象名，严格核对Domain对象名和服务端返回顺序。
- `Read`（服务选择`[4]`）：支持多变量访问和`specificationWithResult`，保留成功Data或DataAccessError选择；RCB根对象Read结果必须是单个`Data.structure`，由独立RCB解码器核对BRCB/URCB字段和BER位串。
- `Write`（服务选择`[5]`）：服务层支持`listOfVariable`多变量写入和常用BOOLEAN、Signed INTEGER、Unsigned、FLOATING-POINT、VisibleString、BIT STRING、BinaryTime、UTC time Data编解码，响应支持逐项成功或`DataAccessError`。当前已在会话工作器中按唯一配置通道执行RCB三阶段Write；遥控、定值写入和报告数据接收仍未接入。

#### 8.1.2.3 MMS Data基础编码扩展

在进入遥控和定值结构编解码前，服务层先提供可复用的有界Data编码辅助：Signed
INTEGER、FLOATING-POINT、BinaryTime和UTC time。FLOATING-POINT必须显式携带
`format-width`（`0x08`或`0x0B`），并拒绝非有限值、宽度不支持或转换后溢出的输入。
BinaryTime使用Unix毫秒时间戳转换为1984-01-01起的天数和日内毫秒；UTC time使用
Unix毫秒、24位二进制定点小数和8位时钟质量编码。所有辅助函数输出完整单个MMS
Data选择，参数错误时清空输出并返回中文错误，不改变现有Worker或Manager接口。

#### 8.1.2.4 MMS控制请求编解码边界

控制编解码层只负责把已完成权限和联锁检查的控制命令转换为协议级请求，不在
MMS收发线程中自行决定是否允许动作。普通SBO选择使用`Read`读取控制对象的
`$SBO`；带值选择使用`Write`写入`$SBOw`；执行和取消分别写入`$Oper`和
`$Cancel`。`$SBOw`和`$Oper`使用有序`Data.structure`，成员顺序为`ctlVal`、仅
`$Oper`可选的`operTm`、`origin`、`ctlNum`、`T`、`Test`、`Check`；`$Cancel`不携带
`ctlVal`和`operTm`，成员顺序为`origin`、`ctlNum`、`T`、`Test`、`Check`。`ctlNum`
按无符号8位MMS Data编码，`Check`固定为2位BIT STRING，`origin`由类别和不超过64字节
的标识组成。

本阶段在对象引用、结构编码和参数边界之上增加第一版控制策略：MMS在线NameList
中的`$SBO`、`$SBOw`、`$Oper`和`$Cancel`成员编译为每个IED的控制能力模型；
模型必须与SCL中FC=CO的数据对象关联，服务端缺少计划内的控制成员时不得把通道标记
为`READY`。在线目录中`ctlVal`的TypeSpecification同时进入控制能力模型，控制Write
发送前必须核对完整MMS Data选择的标签与在线类型；未知在线类型不得静默按标量发送。
普通SBO选择成功后只在当前MMS物理会话内保持；优先使用在线控制对象的
`sboTimeout`，并按控制对象分别计时，缺少该参数的兼容设备才使用5秒默认值。在线
`ctlModel`的direct/SBO语义优先于仅凭`$SBO`名称推断的兼容规则；在线参数非法或
溢出时不能进入`READY`。操作矩阵固定为：0不可控；1和3只允许直接`$Oper`；2要求
普通`$SBO + $Oper`；4要求增强`$SBOw + $Oper`。`$Cancel`只允许在2或4模型中使用，
且必须存在当前物理会话内的有效选择保持。在线NameList与该矩阵矛盾时不得进入
`READY`。控制命令等待窗口按操作类型选择在线参数：`$SBOw`使用
`sboTimeout`，`$Oper`和`$Cancel`使用`operTimeout`；参数缺失时使用5秒兼容默认值。
`$Oper`必须在保持有效且对象相同的选择上下文中执行，
`$Cancel`或成功`$Oper`后清除对应保持。A/B接管、断线、停止和会话代际变化会清除
全部保持状态，不能把旧会话的选择带入新会话。选择、执行和取消的远端响应必须返回
与单项请求数量完全一致的单个成功项后才推进本地状态；失败、超时或取消不得伪造选择成功。
普通`$SBO` Read还必须返回单个非空VisibleString Data；空字符串、其他Data类型或多项
响应都不能建立本地选择保持。在线`ctlModel`必须是INTEGER TypeSpecification，
`sboTimeout/operTimeout`必须是UNSIGNED TypeSpecification，编码值与在线类型不一致时
通道不得进入`READY`。
专用`SelectMmsControl/WriteMmsControl`入口必须命中当前活动通道的在线控制能力模型和
具体对象；空模型或未知对象直接拒绝，不能退化为任意对象的通用Read/Write。权限、联锁、定值策略
和命令结果业务事件仍由后续策略层提供，不能把通用`WriteMms`直接视为遥控能力。
启动计划只要包含FC=CO控制对象，就必须在Initiate请求中声明Write并要求服务端协商
Write；未协商时通道不得进入在线目录和`READY`，不能延迟到首次控制命令才报告失败。

#### 8.1.2.1 受控MMS请求通道

首批控制通道复用已经完成握手和目录核对的MMS会话，暂不新增第三方协议实现：

1. `MmsSessionWorker::ReadMms` 和 `WriteMms` 只接受已进入`READY`且当前为活动通道的会话；没有活动通道、会话仍在配置或正在切换A/B网时返回失败。
2. 请求进入对应Worker的有界串行队列，Worker独占传输对象执行 `ExchangeMmsConfirmedRequest`，异步InformationReport继续由同一分派器暂存和处理。
3. Read/Write的请求和响应均核对`invokeID`、服务选择、结果数量和`DataAccessError`；确认错误、通信断开、取消和请求等待超时分别转换为明确的gRPC状态。普通Read/Write默认等待5秒，控制命令按在线`operTimeout`或`sboTimeout`覆盖该窗口；一次请求保存绝对截止时间，队列、确认响应和CommandTermination共用剩余预算。
4. 调用方超时后请求必须带取消标记；Worker取出或编码后、尚未发送的已取消请求直接丢弃，不能在重连后的新会话中发送旧控制命令。已经发送到IED的MMS Write不承诺远端撤销，调用方返回超时后必须按结果不确定处理并关闭当前会话，由完整重建流程隔离迟到响应。取消标记与完成状态必须通过请求自身的互斥保护，不能在等待线程和会话线程之间产生数据竞争。停止或断线时队列中的请求全部完成为取消/不可用。
5. 该入口只提供协议级读写结果，遥控选择-执行、定值权限、操作前联锁和点表映射属于后续控制策略层，不在MMS编解码器或GOOSE/SV实时线程中实现。

专用控制的能力模型、SBO保持和请求入队必须绑定同一个A/B物理会话；从活动通道取得模型后不得在Read/Write入队时再次选择另一通道。入队时在同一临界区内复核通道仍为READY且允许控制，切换已发生则在发送前返回`UNAVAILABLE`。Initiate始终提议Write以支持受控的通用`WriteMms`；每个物理会话保存服务端实际协商结果，未协商Write时通用Write在入队前拒绝。对含RCB或FC=CO的计划，Write仍是进入READY的强制能力。

增强安全控制的完成语义单独处理：`ctlModel=3`（direct-with-enhanced-security）和
`ctlModel=4`（sbo-with-enhanced-security）的`$Oper` Write成功只代表服务端接受了
请求，不代表动作已经完成。Worker必须在同一MMS物理会话中继续接收
`Unconfirmed-PDU[3]`的CommandTermination InformationReport，核对变量列表中目标
`Domain/$Oper`对象、结果数量和`LastApplError`结构。请求入队前必须为目标对象建立
唯一的执行中状态；仅有一个目标Oper且没有`LastApplError`才算成功，收到成功终止后
才清除执行中状态和SBO保持。包含`LastApplError`时按其中的Error、ctlNum、AddCause
和对象引用返回失败。`ctlModel=4`且在线存在`$Cancel`时保留SBO选择并标记为“待Cancel”，
禁止再次Oper；`ctlModel=3`没有`$Cancel`，远端拒绝已被完整核对时释放本地执行占用，
允许下一次独立Oper。`ctlModel=4`缺少`$Cancel`时无法安全收敛，直接标记结果不确定并
锁定对象。对象、ctlNum、结构或会话无法确认时同样标记结果不确定并锁定对象。
CommandTermination等待受在线`operTimeout`及调用超时上限约束，超时、断线和停止都
不能把旧请求带入新会话。

控制状态表达到容量上限且无法记录新的不确定对象时，状态机会进入全局保守锁定；该锁定
只在MMS会话重建并清空控制状态后解除，不能因为一次记录失败而继续放行控制。

`operTm`的语义按控制模型区分：`ctlModel=3/4`的定时Oper与普通Oper相同，Write ACK
后保持执行中；`ctlModel=3`等待CommandTermination，明确LastApplError后释放执行占用，
`ctlModel=4`等待CommandTermination成功或显式Cancel完成；`ctlModel=1/2`
没有CommandTermination完成事件，Write成功确认即为本地协议终态，随后清除SBO保持，
不建立永久pending。若项目需要确认普通安全模型下的实际定时动作完成，必须另行提供
IED状态/报告关联契约，不能用一个永不收敛的本地pending标志代替。

服务端返回匹配`invokeID`的`Confirmed-ErrorPDU`时，交换器结束当前请求并返回带中文诊断的失败状态；不匹配的错误PDU只记录并继续等待当前请求，非法错误结构直接拒绝，不能按普通确认响应解码。

#### 8.1.2.2 Manager层MMS读写入口

Manager只提供下位机内部控制策略使用的`ReadMms`和`WriteMms`包装入口，当前不把原始MMS请求暴露为gRPC RPC。入口执行以下检查后复制当前`ProtocolStackAdapter`并转发调用：

1. 连接名、输出对象和请求项必须有效；空变量列表或空写入列表直接返回`INVALID_ARGUMENT`。
2. IED必须存在、已启用MMS、协议会话已启动且Manager状态为`RUNNING`。`STARTING`、`DEGRADED`、`STOPPING`、`STOPPED`、错误态以及A/B通道切换期间均返回`FAILED_PRECONDITION`，不向协议栈发起请求。
3. Manager不持有或操作`MmsTransport`，不在锁内等待网络响应；协议栈适配器负责把请求提交给当前已`READY`的活动通道串行队列。
4. 适配器返回的状态和响应原样保留；适配器抛出的异常转换为带中文日志的`INTERNAL`，不能穿出Manager边界。

该入口只承载协议级变量读写，不实现遥控选择-执行、定值权限、联锁、点表映射或安全策略。上述策略必须在调用Manager前完成，不能通过绕过Manager直接访问传输层实现。

所有MMS服务解码器采用事务式输出：请求或响应的任一后续字段、结果项、数量或尾部TLV校验失败时，输出对象保持清空，不交付前面已经解析的部分内容。这样控制请求、目录分页和报告配置不会因半成品数据继续执行。

#### 8.1.3 在线目录第一阶段验收边界

第一阶段实现目录读取、RCB参数读取和目录核对，不提前伪造报告数据：

1. `GetNameList(ObjectClass=DOMAIN, scope=VMD)`分页得到服务端Domain名称，并要求目标计划中的每个逻辑设备可在服务端找到。
2. 对每个Domain分页读取`NAMED_VARIABLE`和`NAMED_VARIABLE_LIST`名称；名称只在当前Domain内解释，禁止跨Domain拼接。对每个计划DataSet调用`GetNamedVariableListAttributes`读取在线成员。
3. 将计划中的SCL数据属性引用转换为MMS对象名：`IEDLD0/LN.DO.DA`对应`domain=IEDLD0、item=LN$DO$DA`；在线响应中的同名对象才可加入目录快照。DataSet和RCB引用使用同样的Domain/Item拆分规则；DataSet成员必须按在线响应顺序映射，不能把SCL静态成员顺序冒充在线成员顺序。
4. 对每个在线数据属性调用`GetVariableAccessAttributes`，保存有界TypeSpecification，并与SCL的`basic_type`和数组`count`核对。BOOLEAN、整数/无符号整数、浮点、可见字符串、UTF-8字符串、八位串和常用时间/品质类型必须拒绝明显不匹配；无法安全判断的类型不得静默当作匹配。
5. 在线目录快照必须携带目标IED和AccessPoint身份，并调用`MmsSessionContract::ValidateOnlineDirectory(COMPLETE)`。缺少目标对象、Domain不一致、DataSet成员数量/顺序不一致、类型不匹配或RCB根对象字段不完整时，通道只能进入错误/降级状态，不能进入`READY`；RCB写入、报告和GI完成后再进行最终就绪确认。

本阶段不把在线目录读取线程连接到DataCenter；RCB配置写入通过独立Write报文完成，写入成功也不能提前报告`READY`。当前工作器已在RCB全部启用后按计划独立写入`$GI=true`，等待带GI Reason的完整报告再进入`READY`。

GetNameList得到的Domain名称用于后续逻辑设备目录读取；逻辑节点、数据集和ReportControl的在线目录快照必须由后续服务请求逐项构造，不能用SCL静态模型替代服务端实际结果。服务层只负责报文和协议字段，不访问SQLite、DataCenter或实时信号总线。

目录核对通过后，适配器按期望的 `rcb_ref` 读取RCB。每个RCB的类型、ReportID、DataSet、`ConfRev`、最大实例数和SCL中声明的触发/可选字段必须一致；实际 `ConfRev` 与期望值不一致时返回配置变更错误，不得静默启用。BRCB/URCB的启用请求必须先写入配置字段，再设置 `RptEna=true`；写入失败或启用确认失败都不能报告Ready。

#### 8.1.4 RCB配置写入阶段

RCB写入使用已协商的MMS `Write`服务，只有启动计划包含ReportControl时才在Initiate中声明该能力。每个RCB由活动配置通道按以下顺序发送独立的有界Write请求；A/B备用通道只完成目录核对，不同时争抢同一个RCB：

1. `$RptEna=false`，先释放本地或上一次会话遗留的启用状态。
2. `$RptID`、`$DatSet`、`$OptFlds`、`$BufTm`、`$TrgOps`、`$IntgPd`配置字段；`OptFlds`为10位BIT STRING，`TrgOps`为6位BIT STRING，均按MMS位串的MSB-first顺序编码。
3. `$RptEna=true`；只有收到每项成功响应后，才在会话契约中确认该RCB启用。

`ConfRev`只用于在线核对和启用确认，不通过Write修改。`GI`不能混入RCB配置字段，必须在所有RCB启用确认后单独写入。为了避免普通报告或旧缓冲报告被误认为GI，启用GI的ReportControl必须同时启用`reasonCode`；只有报告Reason明确包含GI bit4、仍对应当前待完成GI请求，并在分段合并后覆盖完整DataSet且ConfRev一致，才确认对应RCB的GI。未完成GI的会话仍只能保持`CONNECTED`。在通道尚未`READY`期间，收到的完整`InformationReport`只有在它明确对应当前待完成的GI请求时才允许继续进入GI契约核对；普通变化、品质或更新报告必须丢弃并记录原因，不能提前发布到内部实时数据链。GI报告完成核对失败时同样不得发布该报告。

所有要求启用的RCB都确认后，适配器按配置的GI策略发起一次GI；GI响应完整接收并通过分段合并器后，才允许报告 `READY`。仅建立TCP/ISO/MMS连接、仅完成目录读取或仅完成RCB启用都只能保持启动中。会话契约提供逐个RCB的启用确认、GI完成确认和最终Ready判定，ConfRev不一致或未完成GI时判定为未就绪。断线重连时必须重新执行目录/RCB/ConfRev核对，旧会话的Ready状态不能直接复用。

#### 8.1.5 InformationReport解码阶段

报告接收继续使用本项目自研的确定长度BER解码器，不引入ASN.1生成器或第三方IEC 61850实现。MMS报文按以下结构核对：

```text
Unconfirmed-PDU [3]
└── informationReport [0]
    ├── variable-list-name [1] -> VMD对象名 RPT
    └── listOfAccessResult [0]
```

报告字段按RCB的`OptFlds`顺序解析：`RptID`、`OptFlds`、可选的`SqNum`、`TimeOfEntry`、`DatSet`、`BufOvfl`、`EntryID`、`ConfRev`、`SubSeqNum`/`MoreSegmentsFollow`，随后是`Inclusion`、按包含位出现的DataRef、Data和Reason。`OptFlds`必须是恰好10位的BIT STRING，保留位、未使用位和计划中的可选字段必须一致；报告中的`RptID`、DataSet、ConfRev和成员顺序不得用静态配置静默替代。

首批Data解码支持BOOLEAN、BIT STRING、INTEGER、UNSIGNED、FLOATING-POINT、OCTET STRING、VisibleString、MMS String、UTF-8 String、BinaryTime和UTC time。IEC Quality按13位品质位映射到`MmsQuality`；Reason除识别GI bit4外只在协议层校验并随当前内部模型限制丢弃，不得把Reason误当作点值。数组和结构采用有界递归检查，内部`MmsValue`以有序树和原始内容保存；单值、单报告和队列预算同时计算结构内容，超限时拒绝整份报告。下游没有原生结构字段时只能显式映射为`BYTES`，不得静默转字符串或伪造标量。

报告解码输出`MmsReportSegment`，其中`reportRef`使用启动计划中的RCB根引用，`dataSetRef`使用计划中的规范化引用，`segmentNumber`从0开始。只有解码成功的完整字段集合才交给`MmsReportAssembler`；报告接收线程只负责解码、分段入队和有限日志，不执行DataCenter、SQLite或gRPC调用。

报告分段以 `report_ref + sequence_number` 为组键，段号必须从0连续递增，`confRev`和DataSet引用必须在同一组内一致；只有收到最后一段才向上层交付完整报告。缺段、重复段、ConfRev变化或组超时会丢弃整组并记录中文诊断，不得将半份报告发布到DataCenter。分段合并阶段对各段的GI Reason执行逻辑或，因此首段带GI而后续段未带GI时，完整报告仍按GI处理；反之所有段均无GI时不能伪造GI。分段合并阶段同时执行单值256 KiB、单报告4 MiB的逻辑保留内存限制，并最多保留64个在途报告组；超过组数时淘汰最早的未完成组，任何单组超限时整组丢弃。配置阶段等待确认响应时，异步报告按5秒有界等待窗口接收，暂存队列最多保留256份报文且总字节不超过4 MiB，超限时按先进先出丢弃并记录诊断。

Manager在启动前从聚合SCL模型中构造单IED启动计划，只向协议栈传入当前 `ied_name` 对应且已经按 `access_point` 裁剪的 `SclIed`、IED运行配置，以及与 `ied_name + access_point` 精确匹配的 `ConnectedAP` 通信记录。裁剪后的 `SclIed` 只保留目标AccessPoint及其LN、DO、DA、DataSet、ReportControl、GSEControl、SampledValueControl和ExtRef。协议栈不得自行遍历或选择其他IED/AP；启动计划中的DataSet、FCDA和ReportControl是在线目录核对、RCB参数配置、ConfRev检查和GI的目标依据。

每个已启用A/B通道还必须形成一份 `NetworkChannelConfig + SclConnectedAp` 的显式网络绑定。配置了 `subnetwork_name` 时按 `IED + AccessPoint + SubNetwork` 精确匹配；未配置且模型中只有一个匹配ConnectedAP时允许兼容归属，存在多个匹配网段时必须拒绝并要求明确配置。协议栈不得根据数组顺序猜测A/B网归属。

协议栈通过MMS连接事件报告完整A/B通道快照，而不是分步上报单通道变化。状态快照同时携带MMS会话状态、活动通道、每个已启用通道的 `CONNECTING/CONNECTED/DISCONNECTED/ERROR` 状态和错误原因，Manager校验后一次性替换运行快照，避免A/B切换过程中暴露互相矛盾的中间状态。`active_channel`仅表示当前承载MMS报告和控制的通道；未启用MMS或没有可用MMS连接时必须为 `UNSPECIFIED`，GOOSE/SV双网状态不使用该字段表达。

`StartIed`成功只表示协议栈会话引擎已启动。启用MMS但尚未收到有效连接快照时保持 `STARTING`，不得假报通道已经连接；`CONNECTED`只表示MMS传输通道建立，完成在线目录核对、RCB启用和首次GI准备后协议栈才能报告 `READY`，Manager此时才进入 `RUNNING`。同一会话代际只允许为每个通道发布一次从未就绪到 `READY` 的状态边沿，后续普通报告不能无界重复上报 `READY`。连接全部断开时进入 `DEGRADED`，协议栈发生不可恢复错误时进入 `ERROR`。协议栈使用独立的重连尝试事件，每次有效尝试将 `reconnect_count` 增加一次，后续连接成功不得重复计数。

Manager维护独立的会话代际，只接受当前启动代际的事件；停止、重启或删除后的迟到事件必须被忽略。同一IED的协议栈事件必须有序，`StopIed`返回成功后不得再调用该会话回调。A/B均可处于 `CONNECTED`，但同一时刻只能有一个活动MMS通道；默认切换策略由协议栈实现，采用A优先且切到B后不因A瞬时恢复立即回切的稳定策略。RCB接管请求只由明确的`ERROR/DISCONNECTED`或备用通道在低编号通道确认失败后的`CONNECTED`事件触发，单纯进入`CONNECTING`不得打断仍健康的通道。若A在B完成传输建链前失败，B完成建链后必须重新执行RCB配置和GI，接管完成前不得报告`READY`。

启动IED通信功能采用事务语义：MMS、GOOSE或SV任一阶段失败时，协议栈必须按“先停止MMS工作器、再请求GOOSE/SV线程退出、等待线程收敛、最后关闭二层套接字和发布器”的顺序回滚已成功创建的资源；失败返回后不得留下工作线程、报告回调或可占用的网卡套接字，同名IED必须可以再次启动。保护动作发送器的 `Start/Stop` 由独立生命周期锁串行化；发送线程异常退出时会停止接收新动作、丢弃无法回传的在途完成项并记录统计。GOOSE发布失败不得确认保护规则状态，动作保留为pending并按5毫秒起步、最多1秒的指数退避重新尝试，避免发送故障时占满实时消费者线程；成功发送后才清除重试计数。MMS配置失败和保护线程启动失败也必须走统一实时运行时回滚，不能只清除指针。停止IED通信功能时，Manager必须先使当前MMS报告入口及其会话令牌失效，再调用协议栈的停止接口；两项清理都必须执行，不能因其中一项失败跳过另一项。即使协议栈停止失败、底层会话仍可能存活，旧MMS回调也不得继续计数或向DataCenter发布。此时保留最后一次MMS通道快照用于诊断，并保持协议栈会话为活动状态以允许再次停止；在停止成功前再次启动必须返回 `FAILED_PRECONDITION`。协议栈停止错误优先作为RPC结果返回，MMS入口清理错误同时记录中文诊断；协议栈已停止但MMS入口未在期限内收敛时，清除网络快照并返回MMS入口清理错误。模块关闭采用相同顺序和错误优先级。

Manager分别记录协议栈会话和MMS发布管线是否仍待停止。协议栈已经停止但MMS在途调用尚未收敛时，重复 `StopIed` 必须继续调用MMS停用流程并维持错误态，不能因协议栈已不活动而直接报告停止成功；待在途调用实际返回后，再次停止才能进入 `STOPPED`。`Shutdown`首次调用设置关闭门禁，但后续调用和析构仍需重试尚未停止的协议栈会话或MMS管线。

IED处于 `ERROR` 不代表底层资源已经释放。只要协议栈会话或MMS发布管线仍标记为活动，`UpsertIed` 和 `UpsertPointMappings` 必须返回 `FAILED_PRECONDITION`，避免运行中的回调继续使用被替换的配置或点映射；只有两项资源均已停止后才允许修改。

### 8.2 回调约束

协议栈回调只允许：

- 校验最小必要字段。
- 转换为模块内部值对象。
- 写入预分配的有界队列。
- 更新无锁或低争用统计。

协议栈回调禁止同步调用 gRPC、SQLite、文件IO或执行大批量日志格式化。

### 8.3 DataCenter 发布

DataCenter发布线程从队列取出更新，按IED和时间窗口合批调用 `BatchPublish`。队列满时不得阻塞协议栈回调：

- 记录丢弃计数和最高水位。
- 对状态量保留较新值。
- 产生通信质量降级事件。
- 触发可限频的中文告警日志。

MMS报告内部值至少携带 `report_ref`、`data_set_ref`、`conf_rev`、序号，以及每个成员的 `data_ref`、`fc`、原始值、品质、IEC 61850 UTC时标有效性和接收时刻。工作线程按 `data_ref + fc` 查找点映射，再执行类型转换、`scale/offset/deadband`、品质和时标映射；未配置点、类型不匹配、无效工程量和死区过滤分别计入 `mms_values_unmapped`、`mms_values_type_mismatch`、`mms_values_invalid` 和 `mms_values_deadband_filtered`，前三类按次数幂限频记录中文诊断日志，不发布。

`mms_event_queue_capacity`、`publish_batch_size` 和 `publish_batch_window_ms` 为0时分别使用4096个待处理点值、256点和20毫秒默认值。显式配置的上限分别为65536个待处理点值、4096点和1000毫秒；等于上限允许，超过上限在目标态落盘或启动IED通信功能前返回 `INVALID_ARGUMENT`。队列按IED独立限流并按待处理点值总数计算水位；容量不足时逐份淘汰较旧报告，单份报告自身超过该IED队列容量时整份拒绝。DataCenter发布失败不回压协议栈回调，只累计失败统计并限频记录中文日志。

MMS可变长值和发布PDU还必须遵守固定的下位机安全边界，不增加上位机配置项：单个 `STRING/BYTES` 原始值最大256 KiB，单份报告估算保留内存最大4 MiB，每个IED的待处理报告队列估算保留内存最大16 MiB，单个 `BatchPublishRequest` 序列化后最大3 MiB。报告保留内存使用与架构无关的稳定逻辑公式计算：报告固定开销128字节，加 `report_ref`、`data_set_ref` 的实际字节数，再为每个成员累计128字节固定开销、`data_ref`实际字节数及可变值原始内容实际字节数（包括数组/结构的原始TLV内容）；所有加法使用饱和运算，不依赖容器 `capacity()` 或平台对象大小。报告包含超过单值上限的成员，或报告整体超过4 MiB时，整份报告拒绝并分别累计超大值、超大报告和丢弃点数；队列同时按剩余点数和报告保留内存限流，任一预算不足时逐份淘汰较旧报告，部分成员已被批次消费但报告对象尚未出队时仍计算该报告的全部保留内存。DataCenter批次同时按点数和序列化字节数分包，等于上限允许；单个映射点因异常超长tag等原因仍无法放入空批次时只拒绝该点，并累计超大值和丢弃点数。运行统计同时暴露队列字节最高水位，便于评估多IED并发内存。

`deadband` 始终相对于该点最后一次被DataCenter成功接受的工程量计算。DataCenter发布失败不得推进死区基准；品质变化必须绕过数值死区，避免相同数值的 `qchg` 被吞掉。每个IED使用独立发布工作线程，一个IED的DataCenter RPC超时或阻塞不得阻塞其他IED。
同一IED在DataCenter对账后获得新 `conn_id` 时，必须使旧连接的在途批次和死区基准失效，确保后续报告中的相同值也能向新连接发布首值。
DataCenter客户端、注入Stub或诊断适配层抛出异常时，工作线程必须先清除在途 `ClientContext`、复位发布状态并通知等待者，再将该批次计为失败并继续处理后续报告；不得留下悬空取消指针或终止该IED的发布线程。

停止IED通信功能时保留该IED从模块启动以来的累计统计；真正删除IED并完成DataCenter连接墓碑清理后，必须停止专属工作线程并释放队列、映射和统计；同名IED后续重建从空统计开始。
停止MMS入口会先将入口标记为无效并推进会话令牌，再取消在途DataCenter RPC，最多等待1.5秒收敛；因此即使等待超时或后续协议栈停止失败，迟到报告也不能重新进入队列。超过该门限必须向Manager返回 `DEADLINE_EXCEEDED`，IED进入错误态，不能假报已经停止。生产DataCenter同步调用必须响应 `ClientContext::TryCancel()` 或1秒deadline；不响应取消和deadline的自定义Stub违反适配契约，不能通过强制销毁调用栈安全恢复。

## 9. GOOSE 实时面

GOOSE 使用 Linux `AF_PACKET`/raw socket，通过网卡、目的MAC、EtherType、APPID和VLAN过滤报文。每个实时接收套接字使用有界的256 KiB内核接收队列吸收突发，单帧仍限制在预分配的2048字节缓冲内；队列容量不能被解释为允许无界报文或无界内存增长。

网卡适配器将报文解码为协议无关的 `GooseMessage` 后交给GOOSE状态机。状态机严格核对订阅的 `gocbRef`、`datSet`、`goID`、APPID和 `confRev`，拒绝 `ndsCom=true`、不允许的仿真报文和TTL为零的报文；状态变化必须满足 `stNum` 单调递增且新状态从 `sqNum=0` 开始，同一状态下 `sqNum` 单调递增。A/B网收到相同 `stNum + sqNum` 时只接受一次，重复报文不得重复触发保护动作，但应计入重复统计。

二层解码器必须要求APPID载荷声明的PDU长度与实际接收载荷完全一致，并要求 `gocbRef`、`timeAllowedToLive`、`datSet`、`goID`、`t [4] UtcTime`、`stNum`、`sqNum`、`test`、`confRev`、`ndsCom`、`numDatSetEntries` 和 `allData` 等必需字段各出现一次；缺少或重复字段、`UtcTime` 长度错误、截断TLV和超出固定缓冲的字段均拒绝，只有通过完整结构校验的帧才能交给GOOSE实时状态机。

GOOSE `allData` 中的浮点成员使用 `0x87`（FloatingPoint）编码：`FLOAT32` 值首字节为 `0x08`，`FLOAT64` 值首字节为 `0x0B`，后面严格跟随相应的4字节或8字节大端 IEEE-754有效载荷。启动计划必须从SCL基本类型保留该成员宽度；解码时宽度、`format-width` 或长度不匹配，编码时无法表示为有限IEEE-754值，均拒绝整帧。不能把MMS/GOOSE浮点值编码成不带 `format-width` 的裸4/8字节数据。

规范化模型中 `GSEControl@appID` 保存为文本 `go_id`，二层过滤使用的16位数值 `app_id` 只从 `Communication/ConnectedAP/GSE/Address/P[@type='APPID']` 读取；两者不得互相代替。

订阅身份字段不得为空，也不使用空字符串通配符。订阅在启动阶段固化DataSet有序成员的 `data_ref + fc + value_type` 签名，状态机必须逐项核对；成员数量、顺序或类型不一致时拒绝整帧。同一 `stNum + sqNum` 的A/B报文只有载荷一致时才属于正常重复，载荷不一致必须报告冲突并保持上一份有效状态。超时轮询的“无变化”使用独立结果，不计入重复报文统计。

每次有效报文刷新TTL。超过 `timeAllowedToLive` 后状态机只产生一次超时转换，保护输入进入失效态；收到新的有效状态后恢复。状态机不执行DataCenter、gRPC或SQLite调用，保护引擎只消费已接受的状态变化。

首期状态机采用保守的无回绕序号策略：同一订阅会话内 `stNum` 必须严格递增，不把较小的 `stNum` 自动解释为32位回绕。发布端重启或发生理论上的序号回绕时，接收引擎必须先使输入失效并重置该订阅状态，再从新的 `stNum` 接收，避免迟到旧报文跨回绕窗口被误判为新状态。

接收处理至少校验：

- `gocbRef`、`datSet`、`goID`。
- `stNum`、`sqNum`。
- `timeAllowedToLive`。
- `confRev`、`ndsCom`、`test`。
- 数据集成员数量和类型。

关键路径为：

```text
GOOSE接收 -> RealtimeSignalBus -> ProtectionEngine -> GOOSE发送
                                           |
                                           +-> 非实时队列 -> DataCenter
```

保护和联锁动作不得依赖 DataCenter、gRPC 或 SQLite。DataCenter只接收动作结果、状态和事件副本。

### 9.1 首期保护/联锁引擎

首期先实现协议无关的配置化布尔规则引擎。规则由 `IedConfig.protection_rules`
下发并随目标态持久化，每条规则包含：唯一 `rule_id`、一个或多个输入条件、可选联锁输入、
GOOSE输出控制块引用、动作值、释放值以及动作/释放延时。输入和联锁引用使用稳定的
`data_ref + fc`，输出使用稳定的 `control_ref`，启动时才解析为当前会话的运行编号。输入条件之间采用逻辑与关系；联锁输入
必须为有效的布尔值且全部为假，任一输入缺失、通信无效或超过 `max_age_ms` 时规则进入安全
释放态。首期比较器覆盖布尔真/假、等于、不等于、大于、大于等于、小于和小于等于，输出
值必须与目标GOOSE DataSet成员数量和类型逐项一致。

引擎只在实时消费者线程内更新固定大小的输入快照和动作队列，不执行DataCenter、gRPC、
SQLite或动态内存分配；规则条件满足后按动作延时排队一次GOOSE状态变化，条件解除或联锁
生效后按释放延时排队释放值。动作队列溢出时保持待执行状态并累计诊断，不能把未发送动作
误记为已执行。发送线程的完成队列使用固定容量；停止或发送线程请求退出后，完成队列空间
不足时必须放弃未能回传的完成记录并结束线程，不能无限等待实时消费者。会话代际变化、停止
或启动新的IED通信功能时清除所有输入和待执行动作。

本阶段不宣称实现具体厂站保护定值或SV算法；模拟量阈值、保护公式和动作时限在SV算法阶段
根据项目定值表继续扩展。

发送侧必须实现 `stNum/sqNum` 和自动重发。当前下位机默认采用首次1毫秒、随后按1/2/4/8毫秒指数递增、最大1000毫秒的曲线；同一状态持续期间按最大间隔继续重发，状态变化或显式发布会重置为首次间隔。重发线程只调用已打开的二层发布器，不调用DataCenter、gRPC或SQLite；停止IED通信功能时必须先唤醒并等待重发线程退出，再关闭发布器。

## 10. SV 实时面

SV接收使用 raw socket，按网卡、目的MAC、APPID和VLAN过滤。SavPdu外层必须包含 `noASDU [0]` 和 `seqASDU [2]`，声明数量必须与实际ASDU数量及启动计划一致。接收侧至少校验：

- ASDU数量和长度。
- `svID`。
- `smpCnt` 连续性和回绕。
- `confRev`。
- `smpSynch`。

SV二层解码器必须要求APPID载荷声明的PDU长度与实际接收载荷完全一致，拒绝重复的外层/ASDU必需字段、截断TLV和超出固定缓冲的字段；完整结构校验通过后才交给采样计数状态引擎。
- 配置的采样值布局。

SV ASDU按IEC 61850-9-2的上下文标签解析：`refrTm [5]`（`0x85`）必须为8字节
`UtcTime`，`smpRate [6]`（`0x86`）必须与启动计划一致；两个字段不能互换，也不能将
`refrTm`误当作采样率继续处理。

SCL中的 `smpRate`按IEC 61850语义解释为每个额定周期的采样点数，而不是绝对采样率。
因此绝对采样率为 `smpRate * nominalFrequencyHz`；IED配置中的
`nominal_frequency_hz`为0时使用50Hz，显式值只允许50Hz或60Hz。SV原始采样只进入按启动计划预分配的数值环形缓冲区，不逐帧写
DataCenter或gRPC。

首期数学链路只接受 `nofASDU=1` 的SV流，并按一个额定周期收齐窗口后计算单通道RMS。
派生量使用稳定的 `SV_DERIVED/<streamId>/RMS/<inputDataRef>` 引用，作为普通实时信号
继续送入实时快照和保护引擎。窗口不足、品质无效、非有限值或采样计数缺口时清空窗口，
不得计算或发布派生量；计算在唯一实时消费者线程执行，SV raw socket回调只负责校验和入队。
配置中的 `SV_DERIVED` 点映射必须在启动计划中找到同名 `data_ref + fc` 且类型一致的
派生定义，未知引用或类型不一致在创建协议资源前拒绝启动。

相量、频率、功率和多相保护算法在额定频率、通道布局、比例系数、计算窗口、误差要求和
阈值确认后继续扩展，不能把未确认的通道顺序或比例写死在协议解码器中。

SV专用算法开始实现前必须补充：采样率、额定频率、通道布局、比例系数、同步方式、计算窗口、误差要求、保护公式、阈值和动作时限。

## 11. 协议栈适配边界

业务代码只依赖 `Iec61850StackAdapter`，适配接口覆盖：

- 全局初始化和释放。
- 接收Manager生成的单IED启动计划，不直接依赖完整SCL聚合模型。
- MMS会话建立、断开、目录、读写、控制和报告回调。
- GOOSE订阅、发布和取消订阅。
- SV订阅和取消订阅。
- 协议栈错误码到模块错误的转换。

测试提供 `FakeIec61850StackAdapter`，能够注入MMS连接快照、A/B切换、重连尝试、报告、GOOSE、SV、超时和断线事件。

协议栈适配器的 `StopIed` 必须同步取消该IED的报告、GOOSE和SV回调；返回成功后不得再调用注册回调。回调实现不得同步重入Manager控制面接口，只能投递到对应数据面队列。

协议栈适配器的启动、停止和释放接口即使抛出C++异常，也不得穿出Manager控制线程或模块线程；Manager必须转换为中文 `INTERNAL` 错误，保留未完成的资源活动标志并允许后续重试。模块关闭处理某个IED异常后仍需继续处理其他IED。
模块仍必须对迟到回调防御：每次启用MMS数据入口生成新的会话代际令牌，回调只持有管线状态的弱引用和注册时令牌。停止、重启或删除后，旧会话回调即使被协议栈错误保留也不得进入新会话，且不得因Manager析构产生悬空指针。

当前旧项目中的 `libiec61850comm.so` 二进制为32位ARM，不能直接链接到MskDSP的x64或ARM64产物；该历史库不进入当前构建，也不作为自研协议栈的运行时依赖。当前实现优先使用仓库内手写的 ISO-on-TCP、COTP、Session、Presentation、ACSE、BER 和 MMS 编解码。只有在后续明确出现目标IED互操作性缺口、且自研实现无法满足时，才单独评估外部协议库的源码、许可证、目标架构和发布方式，不把外部库作为默认前提。

## 12. 品质和时标

IEC 61850品质先映射到DataCenter现有三态：

| IEC 61850 | DataCenter |
| --- | --- |
| validity=good 且无关键异常标志 | `QUALITY_GOOD` |
| validity=questionable | `QUALITY_UNCERTAIN` |
| validity=invalid 或通信失效 | `QUALITY_BAD` |

detailQuality、source、test、operatorBlocked等详细标志保留在模块内部最新值和诊断接口中。后续如果DataCenter扩展品质结构，再增加无损映射，不使用额外伪造点代替品质字段。

IEC 61850 UTC时间转换为Unix毫秒写入 `ts_ms`；无时标或时标无效时使用接收时间，并将品质降为不高于 `UNCERTAIN`。时间精度、clockFailure和clockNotSynchronized保留在诊断信息中。

## 13. 线程和实时约束

### 13.1 RealtimeSignalBus契约

`RealtimeSignalBus`只承载模块内部保护和计算需要的定长标量信号。字符串对象引用、protobuf消息、STRING/BYTES值和DataCenter发布对象不得进入实时总线；启动IED通信功能时必须先把SCL引用和点映射编译为连续的32位 `signal_id`。

每个协议生产者使用独立的预分配SPSC环形队列，A/B网、GOOSE和SV不得并发写同一个生产者队列。总线只允许一个实时消费者按轮询顺序合并各队列，创建完成后不再增加生产者或改变容量。`TryPublish` 和 `TryConsume` 不执行动态内存分配、日志、锁、gRPC、SQLite或DataCenter调用。

每份更新固定携带 `signal_id`、会话代际、来源、标量类型、A/B通道、品质位、单调时标和源序号。生产者令牌及更新中的会话代际必须与总线一致；停止、重启或删除IED时先使总线失效，旧回调即使迟到也只能增加拒绝统计，不能触发保护动作。

关键实时队列满时丢弃新值而不覆盖已经排队的保护输入，并锁存溢出状态；消费者必须把该状态转换为输入失效或安全态。非实时DataCenter镜像使用独立队列和统计，其拥塞不得反向阻塞或使关键实时订阅失效。

| 线程 | 允许阻塞 | 动态分配 | gRPC/SQLite | 建议调度 |
| --- | --- | --- | --- | --- |
| gRPC控制面 | 是 | 是 | 是 | 普通 |
| MMS会话 | 有界 | 是 | 否 | 普通 |
| DataCenter发布 | 是 | 是 | 是 | 普通 |
| GOOSE接收/发送 | 否 | 启动后禁止 | 否 | 实时优先级 |
| SV接收 | 否 | 启动后禁止 | 否 | 实时优先级 |
| SV计算 | 否 | 启动后禁止 | 否 | 实时优先级 |

实时线程启动前完成缓存、队列和报文对象预分配。IED配置已经提供以下实时线程策略字段：`realtime_cpu_indices`（CPU索引列表，空列表表示不修改系统默认 CPU 集合）、`realtime_scheduling`（`UNSPECIFIED`/普通 `SCHED_OTHER`、`FIFO`/`SCHED_FIFO`、`ROUND_ROBIN`/`SCHED_RR`）、`realtime_priority`（普通调度必须为0，FIFO/RR必须在目标系统允许的范围内）以及 `realtime_failure_mode`（`DEGRADE` 或 `STRICT`，未指定按 `DEGRADE` 处理）。

启动 IED 通信功能时，Manager先完成策略字段校验，然后将同一份策略传给 GOOSE/SV接收、GOOSE重发、GOOSE超时、实时消费者和保护动作发送线程；每个线程在进入任务函数前同步调用 `StartThreadWithRuntimePolicy`。GOOSE首次发布调用由保护动作发送线程或调用方同步执行，MMS会话和DataCenter发布线程不使用该策略，继续采用普通线程调度。

运行时先尝试设置 CPU 亲和性，再尝试设置 FIFO/RR 调度和优先级；空 CPU 列表或普通调度不修改对应系统属性。配置校验只能发现重复/越界 CPU 索引、非法策略和优先级范围，目标 CPU 是否在线、进程是否被允许使用以及实时调度权限仍由线程入口的 Linux 调用判定。策略应用状态包含实际调度策略、优先级、亲和性是否成功和降级状态；保护动作发送器及实时运行时保存相应状态，其他协议线程通过中文日志报告结果。

`DEGRADE` 模式下设置失败记录中文警告并继续运行，已经成功应用的部分保留，失败部分使用系统现有设置；`STRICT` 模式下任一设置失败会使该线程不执行任务函数，并将权限/可用性错误返回启动路径，已创建的 IED 通信资源按事务顺序回滚。该代码路径已经存在，但目标板验收仍必须确认实际权限、CPU 集合、线程抖动、CPU占用和保护动作端到端时延，不能仅凭配置成功或线程启动成功宣称满足实时指标。

同一模块实例内的完整目标态应用、IED增删改、启动IED通信功能、停止IED通信功能、DataCenter对账和模块关闭必须串行执行。较早发起但较晚返回的协议栈操作不得覆盖后续操作的最终状态。

## 14. 权限和部署

- MMS只需要普通TCP网络权限。
- GOOSE/SV需要 `CAP_NET_RAW`。
- 由程序创建或修改VLAN接口时需要 `CAP_NET_ADMIN`；若系统预配置VLAN则不需要。
- `SCHED_FIFO/RR` 通常需要 `CAP_SYS_NICE` 或系统 `rtprio`/cgroup 配置；CPU 亲和性还受进程 cpuset 和目标 CPU 在线状态限制。
- GOOSE/SV 创建 AF_PACKET 套接字所需的 `CAP_NET_RAW` 与线程实时策略权限是两类独立条件。缺少 `CAP_NET_RAW` 时对应 GOOSE/SV 通信功能无法创建套接字；缺少实时策略权限时，`DEGRADE` 允许线程以系统现有调度继续运行，`STRICT` 则使 IED 通信功能启动失败。两种情况均不阻止控制面模块本身启动，但必须返回并记录明确中文错误。

协议栈在创建GOOSE/SV线程和AF_PACKET套接字前执行启动计划校验：启用的每个订阅或采样流必须有唯一的非零ID、非空控制块和DataSet引用、至少一个成员以及至少一个端点；端点必须指定A/B通道、网卡、目的MAC和非零APPID，VLAN参数必须在标准范围内。任何重复ID或非法计划都在资源创建前失败，不得向Manager发布已启动状态。

## 15. 持久化和配置收敛

- 运行时配置统一由ConfigPusher通过gRPC下发。
- 模块将已确认配置和规范化模型保存到 `./conf/config.db`。
- `package/conf/configPusher/iec61850.jsonc` 只作为下发模板，不作为模块直接读取的运行时配置。
- 配置下发使用全量收敛语义：JSONC未声明的旧IED在停止后删除。
- 模块重启后恢复配置；只有模型、通道和点映射满足最小运行条件的IED才允许自动启动通信功能。
- 删除IED时先持久化 `pending_delete` 墓碑，再删除DataCenter连接；DataCenter删除失败时保留墓碑，模块启动对账和周期对账持续重试。DataCenter返回成功或连接不存在后，才删除本地IED、点映射和运行态。

### 阶段C：MMS控制

- 遥控、设点和定值读写按选定协议栈能力实现。
- 在线`ctlModel`、`sboTimeout`和`operTimeout`已纳入控制能力模型；`$SBOw`、`$Oper`和
  `$Cancel`使用对应在线等待窗口，缺失时回退兼容默认值。

- CommandExecutor通过独立共享取消状态把RPC取消传入MMS Worker，不把`ServerContext*`保存到异步队列；排队请求直接取消，已发送但未确认的控制按结果不确定处理。
