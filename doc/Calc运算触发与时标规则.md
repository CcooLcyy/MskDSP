# Calc 运算触发与结果时标规则

## 配置

分组配置增加以下字段，供上位机在 Calc 分组配置界面中选择和下发：

- `trigger_mode`：`TRIGGER_MODE_ON_CHANGE` 表示变化触发，`TRIGGER_MODE_PERIODIC` 表示周期定时；未设置时按变化触发兼容旧配置。
- `period_ms`：周期定时的执行周期，单位为毫秒。`TRIGGER_MODE_PERIODIC` 模式下必须大于 0；变化触发模式忽略该字段。

配置修改后需要先停止分组，再通过 `UpsertGroup` 下发新配置；配置校验失败时不会启动分组。

## 变化触发

计算项收到任一已配置的路由输入更新时开始一轮计算，并缓存各输入的最新值。结果发布前必须具备全部必要输入；同一轮中某个输入重复更新只覆盖缓存值，不重新匹配一组其它输入。结果时标取本轮最先到达的路由输入时标。结果发布后清除本轮首触发状态，下一条输入更新开始新一轮。

求值因输入缺失、类型错误或除零而失败，以及向 DataCenter 发布失败时，本轮不结束，继续保留首触发时标；后续输入更新会使用最新缓存重试。停止分组功能或更新配置会清除未完成轮次。

例如 A(100)、B(110)、A(120)、C(130) 依次到达，A(100) 开启本轮，计算使用最新 A/B/C 值，结果时标仍为 100；发布后后续输入开启下一轮。

## 周期触发

周期触发按基于单调时钟的固定节拍执行，输入使用缓存的最新值；结果时标取周期求值完成时刻（模块产生计算结果时的系统毫秒时间戳）。周期触发不要求输入在本周期内再次到达。若一次计算超过一个或多个周期，跳过已错过的节拍，不连续补算。

## 上报

每次计算结果均提交给 DataCenter。结果值、品质或时标发生变化时，DataCenter/下游按点变化规则进行变化上报；IEC104 遥测点即使数值未越过死区，只要品质或时标变化也应自发上送。周期触发即使结果值不变，也会因周期时标变化形成新的结果更新。周期线程随分组运算功能启动和停止，不会在分组停止后继续计算。

IEC104 需要在报文中携带 Calc 结果时标时，应配置 `point_with_time=true`；否则仍会触发上送，但使用不带时标的 ASDU 类型。若要求批处理窗口内的每次周期结果都形成独立报文，还应配置 `point_dedupe=false`，避免同一 IOA 的多次更新在合包窗口内只保留最新值。
