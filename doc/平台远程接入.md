# 下位机平台远程接入

## 目标与边界

下位机主进程增加独立 PlatformAgent 连接功能，主动接入平台已有 gRPC 入口。平台在线能力不依赖 ConfigPusher、业务模块启停或现场采集任务。默认禁用，不改变现有模块配置来源。实现后用户另外授权 x64 服务器隔离编译测试；不部署、不操作真机或既有服务。

规范协议为 MskDSPPlatformProto 的 `platform/v1/remote.proto`；本仓库固定镜像位于 `platform-proto/platform/v1/remote.proto`，通过独立 `platformRemoteProto` 目标生成；现场接入配置 RPC 位于业务 `protobuf` 子模块的 `ModuleManager.proto`。变更镜像前应与三端规范同步并核对字节一致。

## 输入、输出与目标解析

连接功能固定接入 `60.208.15.90:50000`，统一明文 gRPC。现场直连上位机通过 ModuleManager 的 `GetPlatformAccessConfig`、`SetPlatformAccessConfig` 配置开关、身份和 SSH；读取只返回令牌是否配置。主进程仅加载 `./conf/platform_access.json`，不再从环境变量读取平台接入参数。无文件默认禁用，坏文件报告错误并禁用。完整字段、修订和空令牌语义见[平台接入出厂配置方案](平台接入出厂配置方案.md)。

持久文件以 0600 权限保存，拒绝符号链接，通过同目录临时文件、文件同步、原子替换及目录同步提交；不进入公共配置数据库或导出。保存先落盘再通知独立控制线程切换连接功能；旧连接及隧道取消回收后再接入新身份。保存内容相同不重连，旧连接回调不能覆盖新修订状态。文件替换成功但目录同步失败时报告持久化耐久性不确定、返回新修订且暂停接入，不能声称旧文件未变；重新保存可重试同步。

Hello 的 `agent_version` 为组件协议标识 `platform-agent.v1`，用于区分平台连接组件协议能力，不是下位机发布版本。启用后先发送 Hello，再按照 Welcome 的间隔发送携带完整可用服务集合的心跳。断线自动重连，不恢复旧隧道或重放业务字节。

`ModuleManager` 固定映射本机环回管理服务；普通模块必须位于白名单，且在本机 `GetRunningModuleInfo` 返回的运行集合中。仅提取已知模块监听端口并连接 `127.0.0.1`，不跟随返回地址的 IP。`ssh` 必须本机显式启用。远端不能提交目标 IP、端口或 Unix socket 路径。

## 隧道生命周期与异常

收到 TunnelRequest 后，先重新查询运行模块、校验服务，再连接本机目标；成功后才 AttachTunnel，失败发送中文 TunnelFailure。每设备最多 16 条活跃隧道；每帧最多 64 KiB，空帧和半关闭后数据均拒绝。采用同步流直接背压，不建立无界队列。

本机 TCP EOF 只发送 half_close；平台 half_close 只关闭本机 TCP 写端。保留另一方向直到半关闭完成或收到关闭/取消。握手 10 秒、连接目标最多 5 秒、发送阻塞最多 30 秒。控制流停止、心跳失联、主进程请求停止时取消所有隧道，唤醒阻塞 socket 和 RPC 并回收线程。

日志仅包含消息类型、设备 ID、服务、隧道 ID、方向、字节数和中文关闭原因；不记录令牌、票据、原始业务数据及终端内容。

## 2026-10-20 CI 遗留子模块地址回归

下位机流水线 83 在准备 protobuf 阶段失败，尚未进入编译。两个失败工作区的父仓库已更新，新 gitlink 为 `175c7ef`，但 protobuf 子仓库仍在旧 `b9cc65b`，缺少新提交对象且 origin 仍指向原 GitHub SSH 地址。Runner 重新初始化父仓库时没有注册子模块，先执行 sync 会跳过未注册项；随后 update 的初始化不会同步已有子仓库 origin。旧提交对象本地已存在时该问题被隐藏，新 gitlink 需要 fetch 才触发失败。

修复仅调整 CI 的 protobuf 获取顺序：先 init 注册，再 sync 同步已有地址，最后 update 获取固定 gitlink，所有命令显式限制到 protobuf。认证仍只存在子进程环境中，失败仅显示初始化、同步地址或更新提交阶段，不输出底层日志、远端凭据或认证头。

回归使用真实临时 Git 仓库：父仓库未注册、子仓库旧 origin 指向本机不存在路径、新 gitlink 对象仅存在正确本机仓库。先确认原脚本失败，再验证修复后 origin 被更新且检出新提交；不连接 GitHub 或真实 GitLab，不修改 Runner 工作区和配置。

授权 Ubuntu 隔离容器中，真实 Git 回归在原脚本下实际失败（1 条测试，返回 1），修复后 `test_build_lower.py` **17/17**、`test_init_platform_proto.py` **5/5** 全部通过且未跳过，`bash -n` 通过。测试覆盖三个失败阶段的安全提示与编译门禁，模拟底层输出包含测试令牌时也不会泄露。此轮仅验证获取和编排脚本，不重复编译业务；实际 GitLab 全量构建以随后流水线结果为准。
