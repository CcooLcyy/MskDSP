# 工程量 Decimal20 定点精度改造方案

## 1. 背景与目标

当前 Calc、AGC、AVC、Modbus、DLT645、IEC104、IEC61850 等模块在配置、工程量换算、控制计算、死区判断、限幅和设备写入反算中普遍使用 `double`。这会使 `0.1`、`0.2` 等十进制数在进入业务计算前变成二进制近似值，并在死区边界、连续乘除、舍入和协议量化时产生不可控差异。

本次改造统一采用 Decimal20 语义：

- 固定保留小数点后 20 位，而不是 20 位有效数字；
- 十进制文本输入能够完整保留 20 位小数；
- 每次乘法和除法完成后立即量化到 20 位小数；
- 加法、减法、比较、死区和限幅在固定比例整数上精确执行；
- 到达设备或协议边界后，再按协议规定的字段类型和精度二次量化；
- 不改变 IEC104 短浮点、IEC61850 MMS 浮点、DLT645 IEEE 浮点和 Modbus 整数寄存器的线协议格式。

`boost::multiprecision` 的 `set_precision(20)` 表示 20 位有效十进制数字，不能满足上述固定小数位要求，因此不采用该设置作为 Decimal20 的实现基础。

## 2. 范围盘点

### 2.1 纳入改造

| 模块 | 配置或输入 | 业务计算 | 输出边界 |
| --- | --- | --- | --- |
| 公共组件 | 十进制文本、兼容 `double` | 解析、四则运算、舍入、截断、死区、限幅 | 整数、`float`、`double` |
| Calc | 常量、DataCenter 数值、`decimal_places` | 加减乘除、SUM、AVERAGE | DataCenter 点值 |
| AGC | 倍率、偏移、容量、权重、目标、PI 参数、容差、限值、斜率 | 工程量换算、PI、积分、分配、限幅 | DataCenter 控制值 |
| AVC | 倍率、偏移、`kp`、死区、权重和无功限值 | 电压偏差、目标计算、分配、限幅 | DataCenter 控制值 |
| AGVC 公共策略 | 权重、容量、剩余量 | 加权分配、饱和判断 | AGC/AVC 成员目标 |
| Modbus RTU/TCP | 倍率、偏移、死区、写入工程量 | 正向换算、反算、死区 | 整数寄存器或既有设备字段 |
| DLT645 | 倍率、偏移、死区、BCD 文本 | 正向换算、反算、死区 | BCD 或既有 IEEE 浮点字段 |
| IEC104 | 倍率、偏移、死区、设定值 | 正向换算、反算、死区 | 规约整数、归一化值或短浮点 |
| IEC61850 | 倍率、偏移、死区、控制值 | 普通工程量换算、反算、死区 | MMS/GOOSE 规定的浮点或整数类型 |
| ConfigPusher | JSON 配置 | 十进制文本兼容解析 | 各模块 gRPC 配置 |
| MskDSPUpper | 工程量表单和配置导入导出 | 文本校验与兼容字段选择 | gRPC 十进制文本字段 |

### 2.2 不做机械替换

以下路径继续使用其领域或协议规定的浮点类型，仅在与工程量配置交界处做显式转换：

- IEC61850 SV 的 RMS、相量、频率、平方根和三角函数等信号处理算法；
- IEC104 short float、IEC61850 MMS/GOOSE float、DLT645 IEEE float 等协议原生字段；
- CPU/内存利用率、随机仿真、时间间隔等非工程量数据；
- 第三方库和协议栈内部实现。

## 3. Decimal20 表示与公共接口

### 3.1 内部表示

公共类型放在 `src/common/include/mskdsp/Decimal20.hpp`，内部使用 `boost::multiprecision::cpp_int` 保存缩放后的整数：

```text
实际值 = units / 10^20
```

这种表示保证加减、比较、死区和限幅不存在二进制浮点误差。整数部分最多允许 100 位，内部总有效十进制位最多为 120 位；解析和每次运算后都检查该限制，避免异常超长输入或连续运算无限消耗内存。

### 3.2 公共能力

公共组件至少提供以下能力：

- 严格解析十进制文本和科学计数法；
- 从 `int64` 无损构造；
- 从有限 `double`/`float` 显式进入兼容边界；
- 加、减、乘、除及除零检查；
- 按 0～20 位小数量化；
- “半数远离零”舍入和“向零”截断；
- 精确比较、绝对差、死区判断和限幅；
- 工程量正向换算 `raw * scale + offset`；
- 工程量反算 `(engineering - offset) / scale`；
- 带范围检查的有符号/无符号整数转换；
- 到 `float`/`double` 的显式协议或兼容边界转换；
- 固定 20 位字符串和去除无意义末尾零的规范字符串。

通用除法遇到零必须报错。`scale=0` 视为 1 是工程量兼容规则，只能由工程量换算助手处理，不能改变普通除法的语义。

所有可能失败的接口返回明确错误，不使用静默回退。错误至少区分：格式非法、非有限边界值、超出 Decimal20 范围、除零、小数位参数非法、上下限顺序非法和目标协议类型溢出。

## 4. 输入与兼容策略

### 4.1 十进制文本优先

现有 protobuf 中的大部分工程量字段是 `double`。ConfigPusher 通过 `JsonStringToMessage` 直接解析 JSON，类似 `0.12345678901234567890` 的原始文本在进入模块前已经丢失精度。仅把模块内部变量改为高精度类型不能恢复这些数字。

因此工程量配置采用兼容扩展：

- 保留现有 `double` 字段和字段号，兼容旧配置与旧客户端；
- 为需要 20 位小数的字段增加对应十进制字符串字段，命名为 `<原字段名>_decimal`；
- 十进制字符串非空时优先使用并严格解析；
- 十进制字符串为空时回退现有 `double`，通过最大往返精度的十进制文本进入 Decimal20；
- 两个字段同时存在但值不同，以字符串字段为准，并记录中文告警日志；
- 非法字符串不回退 `double`，而是拒绝配置或命令，避免错误配置被静默接受。

Calc 的精确常量使用 `TypedConstant.decimal_value`；DataCenter 精确点值后续通过 `PointValue.decimal_value` 扩展传递。二者均为新增 oneof 分支，不改变现有 bool、int64、double 分支及字段号。

同步命令响应中的请求值、接受值和上下限采用同样的兼容扩展：保留既有 `double` 字段，并增加对应的 `*_decimal` 文本字段。Decimal20 调用链必须填写规范的固定 20 位文本；新消费者优先读取文本字段，旧消费者仍可读取兼容 `double`。

### 4.2 上位机与配置文件

MskDSPUpper 的工程量输入框以字符串维护表单值，校验完整十进制语法和最多 100 位整数；不得先调用 `Number`、`parseFloat` 或以 JavaScript `number` 保存，再生成十进制字段。下发时填写 `*_decimal`，同时可填写可表示的旧 `double` 字段供旧版本回显；读取时优先展示 `*_decimal`。

配置导入导出保留字符串原文。旧 JSON 数字继续可用，但只能获得原 `double` 可表达的精度，不能宣称恢复到原始 20 位小数。

## 5. 运算规则

### 5.1 解析

- 不允许前后空白、空字符串、十六进制、`NaN`、`Inf` 或尾随字符；
- 允许可选正负号、整数、小数和十进制科学计数法；
- 小于等于 20 位的小数补零存储；
- 超过 20 位的小数按“半数远离零”量化；
- 零统一规范为正零；
- 输入文本总长度和指数解析均设置上限，超限返回范围错误。

### 5.2 四则运算

- 加减直接对缩放整数运算；
- 乘法计算 `a.units * b.units / 10^20`，立即按“半数远离零”量化；
- 除法计算 `a.units * 10^20 / b.units`，立即按“半数远离零”量化；
- 乘除均使用整数商和余数判断半数，不经过 `double`；
- 每步结果检查 100 位整数范围；
- 业务表达式保持源码确定的求值顺序，例如先计算并量化 `raw * scale`，再加 `offset`。

### 5.3 舍入与截断

统一默认舍入为“半数远离零”，与当前 `std::round`/`std::llround` 的正负数行为一致：

- `1.5` 舍入为 `2`；
- `-1.5` 舍入为 `-2`；
- 截断始终向零，例如 `1.9` 为 `1`，`-1.9` 为 `-1`。

需要截断的协议必须显式指定，不允许依赖 C++ 隐式类型转换。

### 5.4 死区、限幅和零倍率

- `scale=0` 按现有兼容规则使用 1；
- `deadband<=0` 表示不过滤；
- `abs(current-last) < deadband` 时过滤；
- `abs(current-last) >= deadband` 时上报，精确等于边界必须上报；
- 业务限幅要求 `lower<=upper`，否则返回配置错误；
- 限幅与溢出检查是不同操作：控制计算可显式限幅，协议编码越界默认报错，不能静默限幅。

## 6. 协议边界规则

### 6.1 Modbus

- UINT16、INT16、UINT32、INT32 保持原寄存器宽度、字节序和字序；
- 工程量反算后先按现有规则检查未舍入值范围，再按“半数远离零”转整数，并做二次防御性范围检查；
- BOOL 点继续忽略倍率、偏移和死区；
- 不把寄存器字段改为 Decimal20 或浮点线格式。

### 6.2 DLT645

- BCD 数字从十进制字符直接解析为 Decimal20，不经过 `std::stod`；
- BCD 的位宽、小数位、符号位和字节顺序保持现有规则；
- IEEE 浮点数据项仍按协议规定转换为 binary32；
- 写入前按数据项实际小数位二次量化并检查可编码范围。

### 6.3 IEC104

- short float 继续使用 IEEE 754 binary32 的四字节编码；
- 归一化值、标度化值和整数命令保持既有范围及编码；
- Decimal20 只参与工程量换算、死区和写入反算，进入 ASDU 编码前显式转换。

### 6.4 IEC61850

- 普通点值的倍率、偏移、死区和控制反算使用 Decimal20；
- MMS/GOOSE 模型声明为 float32/float64 时仍按模型宽度编码；
- SV 数学继续使用适合信号处理的浮点算法，不机械改为 Decimal20。

## 7. TDD 与迁移顺序

改造按以下顺序进行，每一阶段先补会失败的测试，再实现：

1. 公共 Decimal20：解析、20 位量化、四则运算、正负舍入/截断、非法输入、范围、除零、死区、限幅和协议整数转换。
2. Calc 真实链路：精确十进制常量、`0.1+0.2`、`1/3` 和 `decimal_places=20`，通过 `GroupManager -> FakeDataCenter` 验证。
3. 协议工程量公共换算：优先迁移 Modbus RTU/TCP、DLT645、IEC104，并增加短浮点/寄存器/BCD 线格式特征测试。
4. AGC、AVC 和 AGVC 分配策略：迁移倍率、偏移、目标、PI、死区、限值、容量、权重和分配，保留现有控制模式与调度行为。
5. IEC61850 普通点值路径：迁移倍率、偏移、死区和控制反算，保持协议原生浮点边界。
6. ConfigPusher 和 MskDSPUpper：同步十进制字段、文本表单、导入导出和兼容回显。
7. 复扫残留浮点：按“工程量业务”“协议边界”“科学算法”“非工程量指标”分类记录，不对后三类做无依据替换。

首批必须覆盖公共工具和至少一条真实业务调用链。协议特征测试用于证明改造没有改变线格式，即使该测试在实现前已经通过，也必须作为回归保护保留。

## 8. 日志与错误处理

- 新增或修改的日志、错误信息和注释统一使用中文；
- 十进制字符串解析失败时记录字段路径和错误类别，不在日志中省略定位信息；
- 使用旧 `double` 回退时，在配置加载或更新阶段记录一次精度兼容提示，不在每次实时计算时重复刷日志；
- 协议编码失败记录连接、点位、目标类型和越界原因，但不修改既有收发报文日志要求；
- 失败不发布部分结果，不复用上一次成功转换的临时值。

## 9. 验收标准

1. `0.12345678901234567890` 能从十进制文本解析并以固定 20 位形式原样表示。
2. `0.1+0.2` 的 Decimal20 结果严格等于 `0.30000000000000000000`。
3. `1/3` 在每次除法后得到 `0.33333333333333333333`。
4. 正负第 21 位恰为 5 时均按半数远离零处理；显式截断按向零处理。
5. Calc 接受 `decimal_places=20`，超过 20 时拒绝，并通过真实 DataCenter 模拟链发布预期结果。
6. 精确等于 deadband 的变化会上报，小于 deadband 的变化被过滤。
7. 零倍率、除零、负数、非法文本、非有限值、上下限反转和目标类型溢出均有确定结果和中文错误。
8. 新十进制配置字段优先于旧 `double`；旧配置不修改也能继续加载。
9. Modbus 寄存器、DLT645 BCD/float、IEC104 short float 和 IEC61850 原生字段的类型、长度、缩放规则及字节布局保持不变。
10. Calc、AGC/AVC 及首批协议模块的既有业务测试继续通过；新增公共工具和真实调用链测试通过。

## 10. 已知风险与退出条件

- 旧客户端只发送 `double` 时，进入模块前已经损失的十进制原文无法恢复；只能保证后续运算遵循 Decimal20 规则。
- DataCenter 若仍只通过 `double_value` 路由工程量，跨模块链路会在该边界发生一次二进制量化；完整保真需要所有相关消费者支持新增 `decimal_value`。
- `cpp_int` 的计算成本高于原生整数和 `double`，实时高频路径迁移后需单独测量 CPU 和延迟；IEC61850 SV 算法不纳入机械替换。
- 协议编码前的范围检查顺序必须由特征测试锁定，避免改造后意外接受或拒绝边界值。
- 任一阶段若需要改变既有线协议字段、控制算法或调度语义，必须停止该阶段并单独评审，不随精度改造一并处理。
