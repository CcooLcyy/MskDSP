# 测试服务器与 ARM64 设备网络区分

## 已确认行为

用户明确要求直接按架构区分：ARM64 是当前 DSP 真机，x64 均为测试环境。上位机继续使用同一“保存并应用”，不增加设备选择、网络模式或应用按钮。

- ARM64：下位机支持普通出口配置时，保存固定提交 `eth0.102`、网关 `192.168.2.1`、空 DNS；保留现有固定出口实际状态确认。
- x64：使用测试服务器现有网络。支持网络配置时显式提交空网络配置，撤销本功能可能遗留的 DSP 专用出口，并恢复本功能记录的 DNS；没有遗留状态时不调用网络命令，不设置服务器默认路由或 DNS。平台身份、令牌和 SSH 参数正常保存。
- 未报告或未知架构：不猜测为 ARM64，不自动下发固定出口，明确提示只能保存平台参数。旧下位机的普通网络字段缺失语义保持不变。

## 协议与实现

`PlatformAccessStatus` 新增只读字符串 `device_architecture = 14`。下位机根据自身运行环境的 `uname` 结果上报，`aarch64/arm64` 归一化为 `arm64`，`x86_64/amd64/x64` 归一化为 `x64`。不根据上位机本机架构、IP 地址或普通网络已保存值推断，不增加 SSH 探测、认证或 DeviceInfo 模块依赖。

上位机 Rust DTO 透传此字段，前端按设备架构构造可选网络参数；x64 对空配置的确认与 ARM64 对固定出口的确认分开，不能继续要求 x64 回传 684 网关。保存及运行状态刷新均保持连接代次、修订和令牌保护。界面显示当前设备架构及对应网络行为。

宿主机安装准备同步按架构执行：只有 ARM64 才准备 networkd 的外部策略保留；x64 与未知架构跳过，不读取或修改 networkd 全局设置，不重启网络服务。该判断不改变镜像与宿主机架构匹配校验，也不操作纵密参数、NAT 或 PPP 程序。

## 验收与验证边界

先补测试，再实现：ARM64 固定出口不回退；x64 能正常保存及确认空网络、不带 684 网关；未知与旧服务只保存平台参数并明确提示；刷新与切换设备不沿用另一台架构；安装准备在 x64/未知时即使 networkd active 也不执行网络命令。

执行相关前端工作流、Rust 平台配置测试、构建与 ESLint、Python 安装及网络回归；C++ 状态上报由 CI 编译验证。分别提交协议、下位机、上位机相关变更并推送；不在本任务中自动部署测试服务器或真机。
