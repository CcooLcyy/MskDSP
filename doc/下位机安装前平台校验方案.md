# 下位机安装前平台校验方案

## 目标与边界

用户已确认：下发前比较目标设备与安装包平台，不匹配或无法确认时停止；安装器独立增加相同门禁，覆盖手动复制安装包后执行的路径。本方案负责安装器，继续使用 configPusher 下发模块配置，不访问设备、不部署、不更改容器切换及镜像身份校验策略。

## 输入、处理与输出

- 从已校验摘要的镜像 config 读取 `os` 和 `architecture`；Docker/OCI 现有清单、摘要与平台关联校验继续执行。
- 使用 Python `platform.system()`、`platform.machine()` 读取执行安装器的宿主机平台；只接受 Linux ARM64、Linux x64，将 `aarch64/arm64` 与 `x86_64/amd64/x64` 分别归一化。
- 在任何 Docker 操作、业务容器删除和模块目录同步前完成平台比较；同版本跳过加载也不能绕过校验。
- 匹配时输出中文日志，列出宿主机与安装包平台；架构或系统不匹配、字段缺失、不支持、宿主机探测失败均非零退出，明确列出双方平台及停止原因，清理临时载荷并保留现场文件。

## 验收与测试

先补隔离测试，确认当前安装器允许错误平台而测试失败，再实现门禁。测试以确定性的宿主机平台替身覆盖 ARM64/x64 匹配、别名、双向不匹配、未知架构、缺失字段、非 Linux 与探测异常；拒绝时断言没有 Docker 加载、容器删除或模块写入，现场模块与配置内容保持一致。完成后执行 `python script/test_make_exe.py` 与 `git diff --check`，设备实测不在本次范围内。
