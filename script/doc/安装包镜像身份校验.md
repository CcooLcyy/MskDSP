# 安装包镜像身份校验

## 目标与范围

离线安装器必须以归档内 config 内容的 SHA256 判断镜像是否相同，兼容经典 Docker save 的 `<摘要>.json` 与 OCI 的 `blobs/sha256/<摘要>` 路径。Docker 经典镜像存储与 containerd 镜像存储的 `.Id` 可能分别表示 config 或 manifest，不能直接把不同类型的摘要当作构建差异。

本次仅修改 `script/make_exe.sh` 生成的安装器，并增加隔离回归测试。不改变发布清单格式、目标配置或远端服务。

## 身份解析与更新流程

1. 校验 Docker 归档只包含一个镜像，定位 config 文件并计算真实 SHA256；路径摘要不一致、缺失或格式错误时终止，不能加载镜像或替换容器。Config、manifest 与 index JSON 元数据最多各 1 MiB，并拒绝重复元数据路径。
2. 若归档有 OCI `index.json`，只接受单镜像的索引。校验被引用 manifest blob 的实际 SHA256，以及 manifest 的 `config.digest` 确实指向上述 config；平台描述必须与 config 的操作系统、架构一致。只有校验关联成功的 manifest 摘要才可作为同一镜像的另一种身份。
3. 查询目标 tag 的本机 `.Id`。它与已验证的 config 或 manifest 摘要相同才直接跳过加载。对于无法直接关联的本机身份，使用 `docker image save` 按查询得到的不可变 ID 流式读取 config，校验摘要后再比较，避免校验过程中 tag 换绑；不将完整镜像额外写入磁盘。
4. 镜像不一致时执行加载，加载失败必须返回非零。加载后再次验证目标 tag 的身份；仍不一致或无法验证时终止，保留既有容器。
5. 身份校验完成后，按已验证的本机不可变镜像 ID 创建临时容器同步模块与配置、替换并运行 `mskdsp` 容器，避免验证后 tag 换绑。Docker 运行失败或容器未处于运行状态，安装器必须返回非零，并输出中文错误说明。

## 异常与验收

多镜像、多平台索引存在选择歧义，安装器明确拒绝。归档校验失败不能执行 `docker load`、删除既有业务容器或返回成功。无法读取已有镜像时允许继续加载可信安装包，但加载后的验证失败必须终止。

隔离测试复制打包脚本到临时项目，生成微型自解压包并模拟 Docker 命令，不访问真实 Docker、`/data/mskdsp` 或工作区 `package/`。测试覆盖经典及 OCI 路径、config/manifest 摘要损坏、manifest 与 config 关联错误、多镜像歧义、同镜像跳过加载、不同镜像更新、未知身份的流式回退、加载失败和容器运行失败。

执行：`python -m unittest discover -s script -p test_make_exe.py -v`。Windows 需要 Git Bash；测试优先使用 `C:/software/Git/bin/bash.exe`，也可通过 `MSKDSP_TEST_BASH` 指定 Bash。
