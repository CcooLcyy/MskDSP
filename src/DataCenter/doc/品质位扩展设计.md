# DataCenter 品质位扩展

## 目标与范围

在保留 `Quality` 四级枚举及现有字段编号的前提下，为 DataCenter 增加组合品质位的承载能力。覆盖单点/批量发布、源与目的最新值缓存、查询、实时订阅及订阅快照；同步命令转发和已接受命令的目的缓存也保持品质位。

本次不修改采集模块、Calc、AGC/AVC、IEC104 的品质生成或消费规则，不增加断线/数据过期判定，不修改上位机页面，不增加品质历史存储。

## 协议

新增 `QualityFlag` 常量，数值与普通 IEC104 品质掩码一致：`OVERFLOW=0x01`、`BLOCKED=0x10`、`SUBSTITUTED=0x20`、`NOT_TOPICAL=0x40`、`INVALID=0x80`；`NONE=0`。常量用于按位或组合，字段类型为 `optional uint32`，不使用单值枚举承载组合。

| 消息 | 新增字段 |
| --- | --- |
| `PublishRequest` | `optional uint32 quality_flags = 6` |
| `PointUpdate` | `optional uint32 quality_flags = 8` |
| `SourcePointUpdate` | `optional uint32 quality_flags = 7` |
| `ExecuteCommandRequest` | `optional uint32 quality_flags = 8` |

批量请求、查询响应和订阅复用上述消息。已有字段及编号不变。

## 品质契约

- 新字段缺席：完全沿用原 `quality`，不推测明细位；返回更新也保持字段缺席。
- 新字段显式存在且为零：表示所有明细位清零，返回更新保留显式零；每次发布完整替换品质，不与上一次按位累加。
- 新字段存在时，兼容摘要统一为：包含 `INVALID` 则 `BAD`；否则任意非零位为 `UNCERTAIN`；零为 `GOOD`。新生产者可以省略旧 `quality`（即 `UNSPECIFIED`），由 DataCenter 生成兼容摘要。
- 新字段存在且旧 `quality` 为明确的非 `UNSPECIFIED` 值时，必须与摘要一致；矛盾请求返回 `INVALID_ARGUMENT`，不更新缓存、不推送订阅、不执行命令。禁止显式零把旧 `BAD/UNCERTAIN` 静默改为 `GOOD`。
- 未定义位原样保留，不截断为一个字节；非零未知位保守归为 `UNCERTAIN`（含 `INVALID` 时仍为 `BAD`），并记录中文诊断日志。后续协议消费者只映射其支持的位，不能直接将整个 uint32 写入报文。
- DataCenter 不校验具体信息对象是否允许某个位，例如遥信不支持 `OV` 的约束由协议适配层负责。
- 批量发布先完成所有品质校验，任一点冲突则整批失败；失败不推进源端 sequence，也不产生部分缓存写入。
- 同步命令在调用目标执行器之前完成品质校验和摘要补齐；目标命令的接受/拒绝规则保持由目标模块决定。已接受命令只更新既有目的缓存，不额外广播或写入源缓存。

## 调用方与上位机对接

新生产者设置 `quality_flags` 后，建议省略旧摘要或按上述规则同步填写。旧生产者保持原调用方式。新增字段仅在升级后的 DataCenter 保证保真，混用旧 DataCenter 时不能保证品质位经过手工构造更新后仍然存在。

上位机后续接入时应以可空数值承接 `quality_flags`，区分“未提供明细”与“明确正常”；位标志可并列展示，原四级品质继续用于兼容展示。本次不更新上位机协议子模块和页面。

## 验收与验证

1. 五个标准位及其组合在单点/批量发布、源/目的查询、实时订阅和快照中保持不变。
2. 缺席、显式零、非零、未知高位能够经过序列化和完整替换；旧客户端仅使用 `quality` 时行为不变。
3. 新品质生成正确的兼容摘要；冲突请求及批量中途冲突均无部分写入。
4. 同步命令将品质位和兼容摘要交给目标模块，接受后目的缓存保留品质；冲突请求不调用执行器。
5. 先补充 GTest 用例再实现；本地不运行构建/静态检查/自动化测试。审查差异后分别提交推送协议仓库与 MskDSP，在使用该协议提交的 MskDSP CI 中验证并跟踪到完成。
